# krishiv-server

**Layer:** L6 (may depend only on crates in L6 or lower; `cargo xtask layering`).  
**Status:** P0-T26 skeleton exists (`router()`, `serve`, `run_blocking`); the real admin API arrives in P3.

## Purpose
Admin and UI API server (REST, OpenAPI), serves the web UI. Today: `/api/v1/version`, JSON 404 for unknown `/api/*` paths, and the embedded SPA (from `krishiv-ui-assets`) with an extension-less-path fallback to `index.html`. Binds loopback by default. Reached via `krishiv server`, which exists only with the `ui` feature of `krishiv`/`krishiv-cli`.

## Key files
Paths are relative to this crate.
- `src/lib.rs` `router()`, `serve` and `run_blocking`
- `src/guard.rs` (P3-T002) `Guard`, the one check every guarded admin-listener route asks: `GuardRequest` (presented token, malformed flag, peer, `GuardSurface`, `Access`: `Authenticated`, `Metrics` = `Monitor` on `System("metrics")`, `Monitor` on `System("system")`, `Operate` on `System("queries")`), `Refusal` (401 / 503 / 403 / 500 fail closed), `TokenGuard` (the start-up token of a server without authentication), `PeerAddr` (the peer `serve_capped` records as `ConnectInfo`: the address for the throttle and, over TLS, the verified client leaf; `peer_of` / `peer_leaf_of`, passed on as `GuardRequest::with_peer_leaf` to `Credentials::peer_leaf`)
- `src/session_guard.rs` (feature `session`) `SessionGuard`: the server's `ServerAuth`, then the ADR 0046 matrix through `RolePolicy` (no role table of its own); a denial writes one `krishiv::audit` record and, with `with_denials`, counts into the server's `DeniedCounts`
- `src/internal.rs` the UI backend (P2-T133 part a): `router_with_ui(source, token)` and `router_with_ui_guard(source, guard)` (GET needs `Access::Monitor`, anything else `Access::Operate`: operator), the `UiSource` trait (system-table rows as JSON, cancel), `/api/internal/{health,queries,queries/{id},queries/{id}/cancel,history,compare,resources,events}`; every route needs the token (`Authorization: Bearer` for any method; the `krishiv_ui_token` cookie, named `krishiv_ui_token_<port>` when `Host` names a port, or `?token=` only for GET), query text is shown with its literals masked, at most 16 event streams share one snapshot a period, every response of that router carries the CSP / `frame-ancestors 'none'` headers, columns are allowlisted per endpoint, `events` is SSE at one event a second
- `src/pages.rs` (P3-T050) the page endpoints: `/api/internal/catalog/{catalogs,{c}/schemas,{c}/{s}/tables,{c}/{s}/{t}/columns}`, `environment` (settings with secrets masked by `redact_entries`: a key the engine classifies sensitive shows `***`, other values go through `krishiv_common::redact`; the event stream opens with the same `environment` event), the SQL editor (`POST sql`, `GET sql/{run}`, `POST sql/{run}/cancel`; a statement is an `Operate` action), `POST session` (trades the Bearer token for an `HttpOnly; SameSite=Strict` cookie; the page keeps no token and sends none in an address), `UiPolicy` + `host_guard` (the `Host` allowlist, `UiPolicy::for_listener`: loopback binds check loopback names + `krishiv.ui.allowedHosts`, other binds only when names are configured; `secure_cookie` when the listener is TLS; a non-GET with an `Origin` must be same-origin; a cookie carries a change only with the page's `X-Krishiv-Csrf: 1`), and the utoipa `ApiDoc` served at `openapi.json`; `tests/ui_pages.rs`; `tests/ui_editor_auth.rs` (real `SessionGuard`: the editor runs as the caller)
- `src/embed.rs` (P3-T071) embedding the UI: `EmbedPolicy` (origins from `krishiv.ui.allowedOrigins`, `frame_ancestors()` = the list or `'none'`, `sign`/`verify` of a link: HMAC-SHA256 over `krishiv-embed-v1\n{query id}\n{expiry}` with a key made at start-up, expiry at most `krishiv.ui.embed.linkTtl` away, constant-time compare), `parse_origins` (an entry that is not `scheme://host[:port]` stops the start), `validate_theme` (colours `#hex`, font names, radii; no URL or CSS text; mirrored in `ui/src/embed.ts`). `internal.rs` wires it: `GET /api/internal/queries/{id}/embed-link[?ttl&theme]` (token) issues `/queries/{id}/profile?embed=1&exp&sig[&theme]`; `GET /api/internal/embed/queries/{id}?exp&sig` (no token, host check only) serves that one query's detail; `GET /api/internal/embed/config` the origins and `hide_attribution`; only a page request with `?embed=1` gets `frame-ancestors <origins>` (and no `X-Frame-Options`), everything else stays `'none'`/`DENY`. `ui/routes.json` is the versioned manifest of deep links (`tests/ui_embed.rs` checks every path serves the shell and matches `ui/src/routes.ts`); `assets()` resolves the shell's relative asset links from a deep link
- `src/admin.rs` `krishiv server`'s admin endpoints (design P3-T001 §3.5): `health_routes` (`/healthz` open, `/readyz` 200/503 from a ready flag, fixed bodies; never guarded), `with_limits` (request timeout 30 s, SSE `/events` exempt; body limit 2 MiB), `serve_capped` (connection cap, graceful shutdown); `tests/admin.rs`
- `src/admin_v1/` (feature `admin-api`, P3-T066 PR-52a, design `P3-T066-admin-api.md`) `krishiv.admin.v1`, the control API: one `AdminApi` trait (`GetVersion`, `GetCapabilities`, and from revision 2 `ListSessions`, `KillSession`, `ListQueries`, `CancelQuery`, `CancelQueriesByTag`, from revision 3 `GetReadiness`, `GetDrainStatus`, `Drain`, `ResumeServing`: `Monitor` to read, `Manage` on the cluster to change; they act through `DrainOps`, the closures `krishiv server` supplies, and a server without them answers `KRISHIV_UNSUPPORTED_FEATURE`) behind two transports. `admin.v1.pb.rs` and `descriptor.bin` are generated by `tools/admin-protogen` (never edited; `--check` in CI job `admin-protos`); `routes.json` (`admin-v1/`) is the REST verb, path and privilege of each RPC; `rest.rs` builds axum routes from it, maps bodies to and from proto3 JSON through the descriptor (`prost-reflect`; unknown request fields are 400, 1 MiB cap, the error envelope with the error class and SQLSTATE), `grpc.rs` the tonic service with real status codes and `krishiv-error-*` metadata, both behind the `Guard` (`Access::Authenticated`; a refusal on gRPC is a trailers-only status); `browser.rs` the rules for browser-borne requests (non-GET needs `application/json` or `application/grpc*` else 415; on a loopback listener a `Host` outside the loopback names and `krishiv.server.allowedHosts` is 421; no CORS headers, a cookie is no credential); `core.rs` (decode, idempotency, call, replay record: shared by both transports), `page.rs` (keyset page tokens bound to the filter), `idempotency.rs` (`request_id` / `Idempotency-Key` store, ttl `AdminConfig::idempotency_ttl`), `action.rs` (the `krishiv::admin_action` record, one per mutating call, no secret); `Guard::authenticate` returns the `Caller` (role and the session crate's `Authenticated`); `session_admin.rs` (feature `session`) `SessionAdmin` (own work needs no privilege, others' needs `Monitor`/`Operate`; an id the caller may not act on is a disguised 404 plus a denial record; own cancel is `user`, another's `admin`), which registers the `admin.v1` surface row in `system.capabilities` (`ADMIN_V1_REVISION`, `preview`). `cargo xtask admin-api` (descriptor and OpenAPI snapshots in `admin-v1/`, freshness, additive against `--base`); `krishiv server` mounts it on the admin listener; `/api/v1/version` stays as a deprecated alias (`Deprecation`, `Link`). A new RPC: the proto, `cargo run --manifest-path tools/admin-protogen/Cargo.toml -- --write`, a `routes.json` row, an `AdminApi` method with its arm in `core.rs` `invoke` and the method in `grpc.rs`, `cargo xtask admin-api --write`, and a higher `ADMIN_V1_REVISION`
- `src/drain.rs` (P3-T066 §5.1) `DrainController`, the pure state machine `SERVING` → `DRAINING` → `DRAINED` (`start` flips the readiness flag first, after the engine's drain flag that `Drainer::start` sets before calling it, and a second call only shortens the deadline or turns exit on; `step(now, held)` answers wait, cancel the rest, or drained after the 10 s stop bound; `resume` is refused once exiting; `refusing_flag` is what the Connect service reads). It owns no queries: `krishiv server`'s `Drainer` drives it, sets `EngineRuntime::set_draining` (new queries that read more than `system.*` get `KRISHIV_SERVER_DRAINING` at admission, so every surface is covered) and cancels with `CancelReason::Drain` at the deadline
- `src/readiness.rs` (P3-T066 §5.2) `Readiness`: the serving flag (read on every probe, so a drain flips `/readyz` at once) plus background `ReadinessCheck`s run every `krishiv.server.readiness.interval` (10 s) within `readiness.timeout` (2 s); a check fails readiness only after `readiness.failureThreshold` (3) failures in a row once it has passed (one that never passed fails on its first failure) and only when required (`auth` always, plus `readiness.required`); `report()` is the per-check detail behind `GetReadiness`; a result older than three intervals is not ready; `admin::health_routes_cached` answers `/readyz` from it with the fixed bodies. `AuthReady` is check 2 (JWKS fetched and fresh, via `ServerAuth::jwks_ready`); check 3 (warehouse store) is not wired yet
- `src/session_source.rs` `SessionSource` (UI over a runtime: system tables, catalog by `SHOW`/`DESCRIBE`, editor runs as the authenticated caller: `Guard::authenticate` hands the `Caller` (for `SessionGuard`, the `Authenticated`; the start-up token's `LocalAdmin` runs in the ordinary session; any other caller is refused), `with_caller_sessions` builds that caller's session with its role and path policy as a Connect session gets; a run belongs to its caller, at most 4 running per caller, a run still running is never forgotten; runs tagged per run and cancelled by tag), `ProfilesSource` (`krishiv ui --profiles`: the stored Parquet profiles, no engine) and `EmbeddedUi` (serves it from a host process, token + stop on drop)
- `src/embedded.rs` `EmbeddedSource` (the UI over one session of a host process: its own queries, operators and memory pools only, cancel through the session, the editor runs in the session itself, the catalog through a copy of it, Environment is its settings; refuses once the session is closed) and `EmbeddedUi::for_session` (loopback, one token, stops on drop and soon after the session closes). Behind `krishiv::ui` (the facade crate) and `krishiv.ui()` (Python); `UiSource::mode` tells the page which console it is
- `src/metrics.rs` `router_with_metrics`, `router_with_metrics_auth` (with a token, `/metrics` needs `Authorization: Bearer <token>`, compared in constant time; a refusal is a JSON 401 and takes no snapshot; an empty token refuses everyone; a disabled `/metrics` stays a 404 for every caller) and `render` (feature `metrics-prometheus` only). `metrics_route` is the route alone, `metrics_route_guarded` the same behind a `Guard` (`Access::Metrics`, every role), merged into `krishiv server`'s admin router
- `examples/console_capture.rs` runs TPC-H queries through an embedded runtime and serves the UI over it; the website's console captures (`site/capture-console.sh` in the docs repo) use it
- `src/tls.rs` (feature `tls`, P3-T002 design §3.5) `serve_capped_tls`: the admin listener over rustls (`tokio-rustls`), ALPN `http/1.1` (and `h2` with feature `admin-api`, for gRPC), each handshake on a task of its own within `HANDSHAKE_TIMEOUT` (10 s) holding a connection slot, the verified client leaf on `TlsCappedStream::peer_leaf`; `tests/tls.rs` (features `session` + `metrics-prometheus` + `tls`)
- `tests/serve.rs` server tests
- `tests/auth.rs` (features `session` + `metrics-prometheus`) the admin listener with configured tokens: per-role access, 401 / throttle 503, open probes
- `tests/metrics.rs` `/metrics` exposition tests (feature `metrics-prometheus` only)

## Extension points
- A page's data: add a handler in `src/internal.rs` reading through `UiSource` and an allowlist of columns; a new system table is a `SystemTable` variant the source must serve.
- New route: add it to `router()` in `src/lib.rs` under `/api/v1/` with its OpenAPI entry.

## Invariants
- Admin REST is a versioned surface: OpenAPI is generated by `cargo xtask admin-api` from the proto descriptor (no utoipa), and `admin.v1` is additive only (design P3-T066 §6).
- `#![forbid(unsafe_code)]`.
- No `unwrap`/`expect`/`panic` in library code; errors carry a Spark error class + SQLSTATE.
- The metrics exporter only reads snapshots (`SnapshotProvider`): it never
  holds the registry, and `/metrics` is registered only with the
  `metrics-prometheus` feature and `krishiv.metrics.enabled` (else 404).
