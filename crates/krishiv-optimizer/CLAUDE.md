# krishiv-optimizer

**Layer:** L3 (may depend only on crates in L3 or lower; `cargo xtask layering`).  
**Real code arrives:** P2 (batch: rule batches P2-T072a, join ordering P2-T073a), P4 (IVM pass).

## Purpose
Query optimizer: rule- and cost-based rewrites, including the IVM rewrite pass.

## Invariants
- Input and output are resolved plans with the same output attributes; the optimised plan is a fixed point.
- A rule returns its input `Arc` when it changes nothing (that is how a batch detects its fixed point) and
  rewrites a shared subtree once (`dag::Rewriter`), subquery plans included; never copy a shared subtree.
- Inferred join filters leave out an `isnotnull` on a side whose push path (single-input operators) reaches a body read twice that `ShareCte` could share: an `Arc` with several parents (carried through the pass's own rebuilds, `dag::rewrite_up_traced`) or a `Shift` body equal to another instance's; the join drops a null key anyway, and the copies stay equal (TPC-H q15's `revenue0`, the #598 regression). Literal comparisons still move.
- Inferred join filters keep `optimize` a fixed point: a side that already implies a candidate (`constraints::held`: through aliases, `cse_*` projections, `Shift`, positional unions, grouped aggregates, joins, row-preserving nodes; a literal `false`) gets nothing, and a side with nothing to add is returned as it is.
- Only deterministic predicates move; folding never changes what a query returns or raises (no overflow,
  no division, no time-zone-dependent cast; a raising call stays in the plan).
- `SUM(x + c)` of a narrow integral column becomes `SUM(x) + c * COUNT(x)` (`sum_rewrite.rs`, one pass after the
  rewrite batch) only where the type range proves no per-row overflow and `|x|, |c| <= 2^16`; floating point and
  decimals are never rewritten. Conditions and the one residual assumption (fewer than 2^46 rows per aggregate)
  are in the module docs; the executor differential test is `krishiv-exec` `tests/planner/sum_rewrite.rs`.
- Eager aggregation moves only calls whose result cannot depend on row order and whose arguments cannot raise (`eager.rs` module docs); it reads statistics only, runs after join ordering, and states each decision in `EXPLAIN VERBOSE`. The executor differential is `krishiv-exec` `tests/planner/eager_aggregate.rs`.
- Derived group keys move above an aggregate only when equal bare keys give equal values (deterministic built-ins over identity-equality key columns; never floats or collations) and the expression cannot raise (a column, a widening integer cast, or integer `+`/`-` proven in range from statistics under ANSI, never from a type's range nor from a `count`'s range, which rests on estimated rows: `AttrStats::range_estimated`); a derived column a call reads, or an output mixing a call and a moved key, keeps the aggregate as it is; the optimized plan stays a fixed point (`tests/it/derived_keys.rs`).
- Late payload joins move an inner equi-join only above filters, projections and joins that do not read the dimension's columns and are deterministic, with at least one non-inner join on the path (join ordering never moves an inner join back across one: fixed point); exact for any key multiplicity (join commutation, no uniqueness assumed); the dimension must be `restrict::repeatable` (computed twice). Tests: `tests/it/late_payload.rs`.
- Payload above the aggregate never guesses uniqueness: the dimension's key is proven unique by the plan (an aggregate grouped by it, through filters, column projections, `Shift`s and joins on another unique key) or by a `Statistics::unique_keys` fact; every path expression, absorbed condition, call argument and `FILTER` runs on any row (`runs_on_any_row`), the calls are `count`/`min`/`max` and integer or decimal `sum`/`avg` (never floating point: the summation order changes), each `sum`/`avg` buffer proven not to overflow (integer `avg`: its double sum exact, below 2^53) over all of `Path'(X)` (8x margin), since the aggregate now also sees the rows the join dropped. Residual assumption (module docs): the bound multiplies by the *estimated* rows (from statistics only, never a default count) with an 8x margin, as eager's rule 2; a true row count above 8x the estimate near the buffer limit could raise where Spark does not. Calls are matched by registry identity, never by name. Batch only: the session's batch planning is the only production caller. The moved join sits above an aggregate, which join ordering never looks through (fixed point); the new aggregate is tried again at once.
- Join ordering re-plans each inner-join tree (through deterministic filters and column selections) from
  `Statistics`; it never adds a cross product, places each conjunct at the lowest join that has its inputs
  (subquery conjuncts as filters), and restores column order only for positional consumers. Inputs are
  ordered canonically, so `optimize` stays a fixed point. An input's own conjuncts are estimated over one view in a canonical
  order (`narrow::conjunct_selectivities`), so a two-sided range keeps the fraction between its bounds (E5a).
- Column equalities `a = b` of one type between join-tree inputs form equivalence classes (`join_order.rs`
  `canonical_equalities`): inputs with columns of one class can join on it even when the query relates them only
  through a third input, and a join or an estimate takes only the equalities that connect columns of a class not
  already equal below it (`Graph::independent`), chosen canonically (a composite key's members first, its
  selectivity on one canonical member, then column-id order), so the plan does not depend on how the class was
  written.
- Restriction (`restrict.rs`): an aggregate joined on its group keys may be reduced by a semi join with the other
  side's key domain; the domain follows inner-join `o = y` equalities (same type, never through an outer join) to the
  subtree that scans fewest rows, so where join ordering puts the aggregate does not decide it. With statistics and
  `krishiv.optimizer.preservedSideSemiJoin` (on; `Options::preserved_side_semi_join`, perf lever K6) the walk also stops at
  the preserved input of a `LEFT`/`RIGHT OUTER` join holding the keys: a key-only semi join there when it keeps at most
  a quarter of that input and the outer join's other input is at least twice the rest (TPC-DS q40/q80); a side already
  holding a semi join on the keys (`reduced`, also through inner joins) gets none. Join ordering's loop orders again
  after `SemiAntiOrder` sorted a stack (a stack's estimate depends on its order). Tests `tests/it/preserved_side.rs`.
- Statistics propagation (`PlanStats`): a filter narrows `min`/`max` of the columns it reads and clears their null
  fraction when null-rejecting; `OR` takes the union of its branches' ranges, `NOT` and unknown predicates leave
  ranges alone, so a range only stays or widens (the proptest in `plan_stats.rs` holds it to that). An equality with
  a literal outside `[min, max]` estimates 0 rows and removes nothing. A join's keys take the smaller distinct count
  (inner: the ranges intersect, no nulls); an outer join's null-supplying side gains the unmatched fraction as nulls.
  `col = col` keeps `1 / max(NDV)` with an unknown count read as the rows (T166 note, section 2); `col = <scalar subquery>` (reading no column, deterministic) reads an unknown count as the rows too and leaves one value (study 26, E10: q15's `= (SELECT max(..))` over an aggregate output), and `col IN (..)` whose elements read no column, are deterministic and include a subquery leaves `k` values the same way (`k` counts a repeated literal once; a known count is clamped to `k` too); only `col = literal` over an unknown count takes the default selectivity. A count from `StatSource::Sampled` (P2-T164 U6: the session samples file columns an equality or `IN` reads before optimizing) is known like any other. Statistics never change results (rows); the error gates of eager aggregation and payload above the aggregate also read estimated rows and ranges, so with them statistics decide which plans may run a call, under the residual assumption stated there;
  `Options::stats_propagation` switches the propagation off for the differential tests.
- Per-rule and TPC-H plan snapshots live in `tests/it/snapshots/`; differential tests run optimised and
  unoptimised plans through the reference interpreter in `tests/it/support/eval.rs`.
- Never changes a user's explicit `repartition(n)`.
- Rules are plan-snapshot tested; IVM pass satisfies Σ incremental == query(Σ inputs).
- `#![forbid(unsafe_code)]`.
- No `unwrap`/`expect`/`panic` in library code; errors carry a Spark error class + SQLSTATE.
