# krishiv-common

**Layer:** L0 (may depend only on crates in L0 or lower; `cargo xtask layering`).  
**Real code arrives:** P0 (registries exist); grows in every phase.

## Purpose
Shared foundation: Spark error classes + SQLSTATE registry (generated by `build.rs` from the vendored Spark 4.2.0 `spark-error-conditions.json` + `krishiv-error-classes.json`; refresh with `python3 tests/scripts/gen_error_classes.py`), typed config registry (`krishiv.*`, `krishiv.experimental.*`), tracing setup.

## Key files
Paths are relative to this crate.
- `src/config/registry.rs` typed registry of the `krishiv.*` keys (the source for the generated config docs)
- `src/config/mod.rs` configuration types and lookup
- `src/experimental.rs` `krishiv.experimental.*` gating
- `src/error/mod.rs` error type carrying a Spark error class and SQLSTATE; `src/error/template.rs` message templates; `src/error/render.rs` `render_with_context` (message plus the SQL span, caret layout of Spark's `SQLQueryContext.summary`)
- `build.rs` generates the error registry from `vendored/spark-error-conditions.json` and `krishiv-error-classes.json`
- `src/secret/mod.rs` typed secrets; `OptionValue::from_user` is the single classifier (ADR 0038)
- `src/redact.rs` redaction of untyped free text
- `src/cpu.rs` start-up check of the CPU features the build targets; `src/stack.rs` big-stack thread helper
- `benches/config_lookup.rs` config lookup benchmark

## Extension points
- New config key: register it in `src/config/registry.rs`, then `cargo xtask docs-config`.
- New error class: add it to `krishiv-error-classes.json` (or refresh the vendored Spark file), then `cargo xtask docs-errors`.
- New experimental behaviour: a `krishiv.experimental.*` key in `src/experimental.rs`, never a Cargo feature.

## Invariants
- No dependencies on other krishiv crates.
- Error classes mirror Spark's `error-conditions.json`; names/SQLSTATEs are API (deprecation cycle before removal).
- Config keys are typed and registered here; `cargo xtask docs-config` / `docs-errors` regenerate docs.
- Secrets are typed (`secret`, ADR 0038): `OptionValue::from_user` is the one classifier; no `Display`/`Debug`
  of a secret type prints plaintext; `redact` is only for untyped free text, never for options.
- Experimental behaviour is gated by `krishiv.experimental.*`, never by Cargo features.
- `#![forbid(unsafe_code)]`.
- No `unwrap`/`expect`/`panic` in library code; errors carry a Spark error class + SQLSTATE.
