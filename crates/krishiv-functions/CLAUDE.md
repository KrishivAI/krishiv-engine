# krishiv-functions

**Layer:** L2 (may depend only on crates in L2 or lower; `cargo xtask layering`).  
**Real code arrives:** P2 (core), coverage push in P3.

## Purpose
Spark-compatible function library: scalar, aggregate, window and generator functions with version-keyed semantics.

## Layout
- `signature`: what the analyzer types calls with (`FunctionKind`, `SparkProfile`, `ArgType`, `Constant`, `CallTypes`,
  `InputType` incl. `OneOf` = Spark's `TypeCollection`, `Inputs` incl. `Built` = an expression builder's overload choice,
  `ResultType`, `Arity`); krishiv-plan re-exports them.
- `registry` (P2-T153): `builtins()` → `Registry::lookup(name, profile)` = `Found(&FunctionDef)` / `KnownUnsupported` /
  `NotFound`. A `FunctionDef` has kind, arity, inputs, result rule, `deterministic`, `since` and `Execution` (`Scalar` =
  `bind_scalar`, `Aggregate(Aggregate)` for krishiv-exec (count, sum, avg, min, max, first, last, any_value, max_by, min_by; `count_if` and the boolean aggregates name `count`/`min`/`max`, the planner rewrites their argument; `first(x, ignoreNulls)` and `any_value` take the flag from a boolean-literal second argument; the three-argument `max_by` is rejected as unsupported), `Evaluator` = the conditionals, evaluated lazily by the exec evaluator). Signatures live in
  `registry/defs.rs` (strings, datetime, aggregates), `registry/math.rs` (math and `try_*`/`mod` arithmetic, typed as the operators through
  `Inputs::Operator`/`TryOperator`), `registry/hashing.rs` and `registry/conditional.rs` (`Evaluator` entries typed through `Inputs::Leading`, `Common`,
  `CommonWithZero`, `Comparable`); arity, determinism, kind and availability come from `vendored/spark-functions.tsv`, generated by
  `tests/scripts/gen_function_registry.py` from Spark 3.5.7/4.0.0/4.1.0/4.2.0 runs (never edit it by hand). Every
  definition must have a catalog row and every scalar definition a binding (tests). Matrix coverage:
  `krishiv-testkit/tests/registry_matrix.rs` + `tests/fixtures/analysis/registry-matrix-manifest.json`.
- `scalar` (P2-T153): the execution binding of registry scalar functions. `bind_scalar(name, &[BindArg], &BindOptions)` →
  `Arc<dyn ScalarFunction>` (`return_type`, `invoke(&[Arg], rows)`), IR-free (Arrow types only) so the physical planner
  (krishiv-exec) calls it per batch. Arguments arrive after the analyzer's implicit casts; strings/binary in any Arrow
  carrier (read as `Utf8`/`Binary`), results in plain carriers. One family module per kernel family (`string`,
  `datetime`, `math`, `arith`, `hash`, `regex`), each with `NAMES` and a `bind` over the argument shape. `BindOptions` holds ANSI, `KernelCtx` (Spark
  version), session zone, the query start instant (`current_date`, `current_timestamp`, `localtimestamp`), the session user (`current_user`, `user`, `session_user`; family `session`) and `decimalOperations.allowPrecisionLoss`. `round`/`ceil`/`floor` bind
  their scale from a `BindArg::Literal`. Operators, `CAST` and aggregates are not bound here.

## Key files
Paths are relative to this crate.
- `src/signature.rs` call-site types the analyzer uses (`FunctionKind`, `ArgType`, `InputType`, `ResultType`, `Arity`)
- `src/registry/mod.rs` `builtins()` and `Registry::lookup`; its `Execution` includes `Window` (run by the window operator, never called without `OVER`)
- `src/registry/defs.rs` string, datetime and aggregate signatures; `src/registry/math.rs` math and `try_*` signatures
- `src/registry/conditional.rs` conditional evaluators; `src/registry/hashing.rs` hash signatures
- `src/registry/catalog.rs` catalog rows loaded from `vendored/spark-functions.tsv`
- `src/scalar/mod.rs` `bind_scalar`; `src/scalar/args.rs` argument handling shared by bindings
- `src/scalar/{string,datetime,math,arith,hash,session,regex}.rs` family bindings (`NAMES` and `bind`); `src/scalar/regex/java.rs` Java-to-`fancy_regex` translation
- `vendored/spark-functions.tsv` generated from Spark runs; never edit by hand

## Extension points
- New scalar function: a signature in `src/registry/`, a catalog row (regenerate with `tests/scripts/gen_function_registry.py`), a binding in its family module under `src/scalar/`, tests in `src/scalar/tests/`.
- New function family: a `src/scalar/<family>.rs` with `NAMES` and `bind`, wired into `bind_scalar` in `src/scalar/mod.rs`.

- `scalar/regex` (`regexp`, `regexp_like`, `regexp_extract`, `regexp_count`,
  `regexp_instr`, `regexp_substr`, `regexp_replace`): Java patterns are
  translated to `fancy_regex` by `regex/java.rs` (ASCII `\d\w\s`, Java's
  `.`/`$`/`^` and line terminators, `\Q..\E`, POSIX `\p{..}`, possessive
  quantifiers as atomic groups, inline flags); the replacement is read as
  `Matcher.appendReplacement` does (errors are `INVALID_REGEXP_REPLACE`).
  A group index outside `0..=groupCount` is
  `INVALID_PARAMETER_VALUE.REGEX_GROUP_INDEX`, checked lazily after a
  match. Unsupported Java constructs, oversized patterns and huge counted
  repetitions are `INVALID_PARAMETER_VALUE.PATTERN`. Patterns with
  back-references or look-around backtrack: one match attempt is capped at
  `BACKTRACK_LIMIT` steps
  (`KRISHIV_REGEXP_BACKTRACK_LIMIT_EXCEEDED`), a deliberate divergence from
  the JVM, which has no limit. The `split` and `regexp_extract_all` pieces
  (array results, which the analyzer cannot type yet) are public helpers of
  the same module, used by the conformance harness. Add new regex functions
  to this family.

## Invariants
- Behaviour keyed by Spark version (3.5, 4.0, 4.1, 4.2), never ad-hoc flags.
- Each function registered compatible / incompatible (opt-in `krishiv.expr.<name>.allowIncompatible`) / unsupported; no global switch.
- Golden tests from spark-semantics before implementation (skill `krishiv-spark-function`).
- Unselected rows never raise (CASE/IF/COALESCE, AND/OR short-circuit).
- `#![forbid(unsafe_code)]`.
- No `unwrap`/`expect`/`panic` in library code; errors carry a Spark error class + SQLSTATE.
