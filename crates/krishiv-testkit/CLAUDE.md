# krishiv-testkit

**Layer:** L7 test infrastructure (`publish = false`; product crates must not depend on it; `cargo xtask layering`).  
**Status:** P0 skeleton (P0-T20..T23); SQL-executing suites are `#[ignore]`d until P2 (SQL) and P4 (streaming).

## Purpose
Conformance harness: Spark `hash()`/`xxhash64()` golden fixtures (`tests/fixtures/spark-<ver>/hash.json`),
the `SQLQueryTestSuite` golden runner over `tests/spark-golden/<tag>/` (`.sql.out` parser, `Engine` trait,
three-number report, exclusion manifest `tests/spark-golden/exclusions.json`; `cargo xtask golden` writes
`target/golden-report.json`; `--engine sql-parse` measures the `krishiv-sql` parser on the DQL statements,
`golden::sql_parse`; `--engine session` runs every statement through `krishiv-session`, `golden::session_engine`),
the frozen statement-level baseline `tests/spark-golden/known-failures.json` (categories and classification rules) with
one file per golden input file under `tests/spark-golden/known-failures-cases/` (`golden::known_failures`: every failing
statement with a category — unsupported feature with its plan task, divergence with ADR 0023, or bug with its owner;
classification rules in the same file, `golden::classify`) and its CI ratchet (test `golden_ratchet`: a newly failing
statement fails, a listed statement that passes must be removed; refresh with
`cargo run -p krishiv-testkit --bin golden-report -- --engine session --ratchet update`), the batch == bounded-stream invariant
harness, a sqllogictest runner over `tests/sqllogictest/`, and the Spark function matrix (P2-T106a):
`tests/fixtures/spark-<ver>/function-matrix/` (generated by `tests/scripts/gen_function_matrix.py` against the
Spark container), loaded by `fn_matrix`, with the coverage dashboard from
`cargo run -p krishiv-testkit --bin fn-matrix-report [-- --results FILE | --kernel-eval]`. `kernel_eval` (P2-T021a)
runs the arithmetic/comparison/cast matrix cells and the literal statements of Spark's arithmetic goldens on
`krishiv-kernels` with a minimal Spark 4.2 implicit-cast typer (tests `kernel_matrix`, `kernel_golden`); it is a
harness, not the analyzer. P2-T023a adds the string functions (`kernel_eval/strings.rs`; `string_case` checks `upper`/`lower`
over every Unicode scalar value against `tests/fixtures/spark-<ver>/case-mapping.json`).
P2-T027 adds the hash functions (`kernel_eval/hash.rs`): `hash_fixture` keeps each case's `conf` and the
`default_conf_errors`; `hash_fixture` (test) runs every case of `hash.json` (nested values built by the evaluator's
`array`/`named_struct`/`map` constructors) and `hash_differential` the seeded random cases of
`hash-differential.json` (`tests/scripts/gen_hash_differential.py`; Spark 4.0/4.1/4.2 agree).
P2-T026 adds the math functions (`kernel_eval/math.rs`) and `math_differential` (seeded random cases of `math-differential.json`,
`tests/scripts/gen_math_goldens.py`; Spark 4.0/4.1 differ from 4.2 in `asinh`/`acosh` only, so their fixtures hold just those groups).
P2-T025a adds the datetime functions and ANSI interval literals (`kernel_eval/datetime.rs`),
session time zones through `kernel_eval::JiffZone` (the tz database behind `TimeZoneRules`, test-side until the session
layer has one), and the fixtures `cast-timestamp-differential`, `dst-transitions` (Los Angeles, Berlin) and
`tpch-date-predicates` (tests `cast_timestamp_differential`, `dst_transitions`, `tpch_date_predicates`).
`registry_matrix` (P2-T153) analyzes every matrix case of a registered built-in function with the production registry
(type, nullability or analysis error class vs Spark, both ANSI modes); failures are listed with reasons in
`tests/fixtures/analysis/registry-matrix/`, one file per function name (`KRISHIV_UPDATE_MANIFEST=1` rewrites
only the changed files).
The generic `FileFormat` conformance suite (`file_format`, P2-T117: 13 checks over a `FormatFixture`,
`file_format_conformance!(name, fixture)`) and its `MockFormat`; every format crate instantiates it, directly and
through the executor (`file_format::drive::ThroughExecutor`, P2-T117b). `file_format::parquet::ParquetFixture`
(P2-T080a) reads through the real Parquet reader and writes through a test-only `ArrowWriter` encoder.
`tests/parquet_interop.rs`: other engines' Parquet files read to pyarrow's values; its TPC-H SF1 test is ignored
until P2-T119 brings the datasets to the nightly box (~1 GB of generated data: `KRISHIV_TPCH_DIR`, see
`tests/scripts/tpch_parquet_checksums.py`).

## Key files
Paths are relative to this crate.
- `src/golden/` the SQLQueryTestSuite runner, report and manifest; `src/file_format/` the `FileFormat` conformance suite
- `src/kernel_eval/` kernel evaluation for the Spark function matrix; `src/fn_matrix.rs` matrix loader
- `src/hash_fixture.rs` hash golden fixtures; `src/batch_stream.rs` batch == bounded-stream harness; `src/slt.rs` sqllogictest runner
- `src/bin/` report binaries; `tests/` the differential and interop suites (e.g. `registry_matrix.rs`, `file_format_mock.rs`, `parquet_interop.rs`)

## Extension points
- New file format: instantiate `file_format_conformance!` in its own crate; new golden suite: a runner under `src/golden/` plus fixtures under `tests/fixtures/`.

## Invariants
- Golden data comes from a real Spark run or the vendored Spark tag, never hand-written (ADR 0008, 0010).
- Ignored tests name the phase that un-ignores them; do not delete them.
- `#![forbid(unsafe_code)]`; no `unwrap`/`expect`/`panic` outside tests.

## ADRs (in `../krishiv-internal/adr/`)
