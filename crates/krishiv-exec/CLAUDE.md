# krishiv-exec

**Layer:** L4 (may depend only on crates in L4 or lower; `cargo xtask layering`).  
**Real code arrives:** P2; hash tables/spill: Opus.

## Purpose
Batch execution engine: operators, pipelines, morsel scheduling within a node.

`join/merge.rs` sort-merge join (P2-T056): `SortMergeJoin` is the source over two `Sort`s in hash buckets of the keys
(`Sort::bucket_reader`, `PipelineBuilder::set_merge_source`), `Merge` the merge of one bucket pair; a key's right rows
are the group, spilled past `krishiv.exec.join.smj.bufferBytes`; `join/fallback.rs` runs a grace partition that will not
split through the same `Merge`. `join/merge/asof.rs` the as-of merge (Spark 4.3's `ASOF JOIN`, `SortMergeJoinPlan::as_of`, codec feature
`as_of_join`): both sorts also order by the as-of column (NULLs first, skipped), groups are the keys alone, and each
left row takes the nearest right row of its group: without a residual two pointers whose place (and backward's candidate)
carries across the left batches of a key, so a group is read once (`AsOfCursor`, metric `as_of_right_rows`); with one,
pairs are evaluated per left batch, forward emits a row at its first passing pair and backward at the first right row past
its value, the open rows' best rows copied out of each read chunk, reserved (`as_of_compact`; gauge `as_of_held_chunks`);
Spark's distance (`AsOfMergeSpec::distance`, planned only when `may_raise`; `AsOfDistance` compiled at instantiation over
a narrow batch of the columns it reads, `isnotnull` so no rule folds it) is evaluated where Spark evaluates it: SQL,
forward only, on a row's match and its next passing row (one row per run matched at one right row); Connect
(`distance_on_every_pair`, Spark's `RewriteAsOfJoin`), every passing pair in both directions, by the key's farthest pair
without a residual (`as_of_finish` reads to the group's end forward); so an ANSI overflow raises where Spark's does; without ANSI a Connect distance, or a SQL forward one, of an integral type, or a decimal one `krishiv_plan::exact_decimal` does not prove exact, is `KRISHIV_UNSUPPORTED_FEATURE` (it would wrap or turn NULL, and Spark's `min_by` or forward comparison then picks by that order); a Connect join, or a SQL forward one, on floating-point values is refused too, ANSI or not (its distances rank unlike the values at the infinities); so is one on `TIMESTAMP` values in a session zone whose offset ever drops, DST or not (historical and LMT steps count, so in practice only UTC or a fixed offset runs; `ZoneRef::local_time_is_monotonic`: Spark subtracts local date-times, so across a DST fallback a later row can be nearer and Spark takes it); timestamp, date, interval and exact decimal distances run; `planner/join/asof.rs` plans `PlanNode::AsOfJoin` onto it (no key: one constant key; runtime-filter
sites on the left only, and none where the residual or an evaluated distance may raise; nearest and tolerance are `KRISHIV_UNSUPPORTED_FEATURE`).

`aggregate/observe.rs` (P3-T084) `Dataset.observe`: `PhysNode::CollectMetrics { input, name, measure, instance, limit }`, a pass-through operator that folds each driver's rows into a global partial `AggTable` (charged to the driver's consumer; `NeedMemory` under pressure) and forwards the batch unchanged; `limit` (set by `planner/observe.rs` `cap_observed` from a `LIMIT` above, through projections only) caps the rows folded, one budget per instance, as Spark counts the rows its consumer pulled. `loops.rs` (T180 unit 5b) `UnionLoopSource`: a recursive CTE (`PhysNode::UnionLoop`/`LoopRef`) as one source. The anchor and each
round of the recursive term run as queries of their own over a child `QueryContext` (child memory pool, cancelled with the
outer query); every batch goes downstream at once and into the round's working table (`shared.rs` `Output::open/append`,
spilled to the query's scope under pressure), which the next round's `LoopRef` reads (`SharedSource::over`). `Detached`
(`physical/instantiate/detached.rs`) instantiates the anchor and each round when it starts, with the loop tables bound; shared plans are built again for each run, their unseeded random calls salted as the outer plan salted them, so an enclosing nondeterministic CTE gives the anchor, round 1 and the outer query one value and round `k` the stream of partition `k - 1`, as in Spark (the runs' own calls take a salt range per loop). Limits (`LoopLimits`) are plan data. Seeded random functions draw round `k`'s stream at partition `k - 1` (`EvalEnv::partition_shift`, as Spark does); a working table of at most 100 rows is read by one driver in order (`Output::read_by_one_driver`), as Spark reads its `LocalRelation`. Not matched: Spark round-robins a larger working table into the shuffle partitions, which Krishiv's drivers do not reproduce. `EXPLAIN ANALYZE` reports the rounds, their rows and the folded compute time and spill bytes of every round, a LIMIT-stopped one included (`add_run_metrics`).

`planner/probe_select.rs` (design P2-E3 U2) fuses a `Filter` (nothing may raise: predicate, keys, residual) and a

`planner/properties.rs` (P2-T174) the ADR 0012 property pass: required distributions and provided placements (by
attribute id); `Exchange` nodes (`Hash` on the routing hash, `Single`, `Broadcast`, `RoundRobin`, `Range`) are inserted

An aggregate over rows that must move is planned in two phases, `Aggregate{Partial}` -> exchange -> `Aggregate{Final}`
over states (`planner/aggregate.rs`, design P2-T174 unit 2; `DISTINCT`: partial over keys and argument, exchange,

partition, `Hll(10)` of the keys) that `EXPLAIN ANALYZE` prints as `exchange_*`.

## Extension points
- New operator: follow skill `krishiv-operator`; stateless ones go in `src/operators/`, stateful ones next to aggregate or join.
- New plan node: a `PhysNode` variant in `src/physical/mod.rs` with its builder in `src/physical/instantiate.rs`; the planner validates it with the same builder.

## Invariants
- All memory through krishiv-memory reservations; every spill path tested with tiny-memory tests.
- Only the driver yields, awaits memory, spills or checks cancellation; `execute`/`sink` stay sync and bounded.
  Exception: a breaker's finished in-memory result, owned by no driver, spills on a task of its own
  (`output_spill.rs`: aggregate and sort results, an aggregate's combined driver tables until `finalize` (`aggregate/sink/combined.rs`), and a hash join build's finished tables until the first probe driver
  reads them, `join/build.rs` `IdleBuild`); the coordinator drops a finalized state after its last reader.
- At query end (success, error, cancel) the query pool is empty: tests assert it.
- Cancellation-safe, no blocking in async; metrics feed EXPLAIN ANALYZE. Exception: the idle round's closures (`idle.rs`) wait up to 5 ms on a worker for their peers, only while no query runs, and end within 1 ms of a query start.
- New operators follow skill `krishiv-operator`.
- Physical plans are serializable data: plan types in `physical/` hold no `Arc<dyn …>`, locks, atomics or cells
  (`PlanData`, `cargo xtask source-guard`); scan sources, spill scopes, runtime-filter and subquery cells are
  created at instantiation. Review question for every change: does this assume one process?
- Security barriers (E14): `planner/barrier.rs` plans a barrier's input with no node of its own, adds its scans to the planner's guarded set and clears its runtime-filter sites (no join's build filters a scan inside it; a barrier's own rows may still filter another scan); probe fusion skips a guarded scan; a scan that decides once (a Python data source) is not asked to decide under a barrier (`Planner::barriers`): it reads with nothing pushed and the whole policy `Filter` stays above it, so no user code takes a policy conjunct out of the plan; `PhysicalPlan::guarded` carries the set (coordinator-side, not in the codec: `without_guarded` for a round-trip comparison; `into_write`/`into_table_write` keep it), and `profile_scans` lists no compared column for a table any guarded scan reads. A pass that reads the set runs on the coordinator; one elsewhere needs a codec mark first (P5). Tests `tests/planner/barrier.rs` and `tests/planner/decided_scan.rs` (the deciding scan).
- `#![forbid(unsafe_code)]`.
- No `unwrap`/`expect`/`panic` in library code; errors carry a Spark error class + SQLSTATE.

## Vector carrier (P3-T075)
`carrier::fixed_to_list` turns a vector carrier into a plain list (shared values, offsets 0,N,2N; null rows get empty slots); `recarried_array` has the FSL to List branch. Expressions never see the carrier: `column()` and `Column::eval` (`planner/eval/mod.rs`) convert on input, while a bare projected column keeps it. Grouping and join keys on lists stay unsupported, vector or not.

`aggregate/theta_sketch.rs` (+ `theta_sketch/` tests) the Theta aggregates (`ThetaSketchAgg`, `ThetaUnionAgg`, `ThetaIntersectionAgg`): the partial state is the serialized sketch; wired through `accumulator`/`fold`/`output`; window use is refused.
