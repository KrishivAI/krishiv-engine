# krishiv-session

**Layer:** L5 (may depend only on crates in L5 or lower; `cargo xtask layering`).
**Real code since:** P2-T090 (session, configuration, catalog, DataFrame actions).

## Purpose
The session every API surface shares: configuration, the session catalog (temporary tables and views),
and the query pipeline (parse → analyze → optimize → physical plan → run). The Rust facade (`krishiv`, L7)
re-exports it; the Python facade and the Connect and Flight SQL servers (L6) wrap the same type.

## Key files
Paths are relative to this crate.
- `src/lib.rs` public entry and re-exports; `public-api.txt` the reviewed public surface
- `src/session.rs` `Session` and the query pipeline entry
- `src/runtime.rs` `EngineRuntime` (design P2-E1): what one process shares — executor, memory root, spill directory, the `IoScheduler` with its file-metadata and block caches and the local store (R3), metrics and format registries, query runner, running-query registry (`reserve`/`attach`/`cancel_where`). Sessions are light children (`SessionBuilder::runtime`; `Session::new_session`, `Session::close`, `Session::sql_with` in `src/session/lifecycle.rs`); a session built alone gets a private runtime, so embedded use is unchanged. Runtime-owned keys (`runtime_owned`: cluster scope, `krishiv.memory.*`, `krishiv.spill.*`, `krishiv.io.*`) on a session builder of a supplied runtime are `CANNOT_MODIFY_STATIC_CONFIG`, as `SET` of one is; `close` and `attach` share the registry lock, so no query registers on a closed session. `krishiv.session.memoryLimit` gives a session its own pool under the root (`TreePool::tenant`). A query's I/O goes through one `IoContext` (`QueryEnv::io`), so `system.queries.bytes_read/written` are its own, not the runtime's totals; `tests/runtime.rs`, `tests/runtime_memory.rs`, `tests/runtime_io.rs`
- `src/cancel.rs` (design P2-E1 §4) `CancelReason` (`user`, `timeout`, `admin`, `quota`, `drain`, `client_gone`) and its error (`OPERATION_CANCELED`, `KRISHIV_QUERY_TIMEOUT`, `KRISHIV_QUERY_KILLED`, all HY008), applied through `QueryContext::cancel_with` (first reason wins; drivers and the stream end with it; `system.queries.state` stays `cancelled`, `cancel_reason` names it), and `Deadlines`, the runtime's one timer task (min-heap of weak queries, `krishiv.query.maxExecutionTime` and `QueryOptions::deadline`, the shorter wins). The runtime's registry entry exists from the query's row on (`EngineRuntime::reserve`/`attach`), so a cancel before the context is kept and applied at attach. APIs: `Session::cancel` (own session), `Session::interrupt_all`, `EngineRuntime::cancel` (any session, not reachable from SQL); `tests/runtime_cancel.rs`
- `src/history.rs` the runtime-wide `system.queries` rows (`QueryHistory`: UUIDv7 minting; at 1,000 rows a principal loses its oldest finished row; `krishiv.system.queries.capacity` evicts the oldest finished row of the principal holding the most, and so does going past 64 MiB of rows (`QueryRow::heap_bytes`); running rows are never evicted), the public `QueryId` (parsed as Java's `UUID.fromString(id).toString`, as Spark Connect does) and `QueryOptions` (`Session::sql_with`: a caller operation id held by the statement's handles, `Operations` per session as Spark Connect's `SessionHolder`: `INVALID_HANDLE.FORMAT`, `OPERATION_ALREADY_EXISTS` while held, `OPERATION_ABANDONED` for 30 minutes after its last use); `system.rs` `QueryLog` is a session's view of it (tags, trace, principal filter; `Monitor` asks the policy for `MONITOR` on `system` to show every principal's rows); `tests/runtime_queries.rs`
- `src/conf.rs` configuration snapshot taken per query (`query_snapshot`, where an unset session time zone is the local zone;
  `snapshot` is the stored configuration, which `SET` lists); `local_zone` reads the machine's zone as Java does
- `src/catalog.rs` session catalog (temporary tables and views; `catalog/scans.rs` `reads_stored_table` (the scans of a plan and its subqueries, each shared expression node once); `catalog/file_tables.rs` `QueryCatalog::open_files` lists and opens the file tables a plan scans, then `catalog/ndv_sampling.rs` samples the distinct values of the file columns an equality or `IN` in its `Filter` conditions compares, P2-T164 U6, within one time budget per query (`krishiv.optimizer.ndvSampling.timeout`), and `sample_notes` gives `EXPLAIN COST`/`VERBOSE` a line per table, `tests/ndv_sampling.rs`; the permanent catalog `store` and `warehouse` are the runtime's, shared by its sessions as Spark's `newSession()` shares them, `SessionCatalog::over`)
- `src/carrier.rs` decimals and calendar intervals at the session's edges: `register_batches` converts to the canonical carrier (`Decimal64`, the calendar struct), results and `schema()` read `Decimal128` and `Interval(MonthDayNano)` (`edge_arrow_type`)
- `src/view_schema.rs` schema binding modes of permanent views (`WITH SCHEMA BINDING|COMPENSATION|TYPE EVOLUTION|EVOLUTION`, Spark's `ViewSchemaMode`): the read projection per mode, the checks against the analyzed view query, the evolved schema stored after analysis; `tests/views_schema_binding.rs`
- `src/dataframe.rs` DataFrame transformations (IR only) and async actions; `src/column.rs` and `src/functions.rs` user API
- `src/query_fold.rs` the bookkeeping around one running query: `QueryStart` (counters read at start), `QueryFold`/`MetricStream`/`PendingFold` (the one fold of its metrics into the engine series and `system.queries` when the stream ends, fails or is dropped; holds the admission permit), `QueuedRow` (the history row of a query waiting for admission)
- `src/admission.rs` the admission seam (E5): `AdmissionController::admit(&QueryRequest) -> Permit` asked once per query in `run_on_query_logged`; default `Unlimited`; a waiting `admit` shows the query `queued` in `system.queries`, a refusal closes the row `failed`, a drop while queued `cancelled`; the permit (slot, optional per-query memory budget) lives in the query's `QueryFold` and releases on drop; `tests/admission.rs`
- `src/access.rs` `StatementInfo` / `Session::statement_info` (class + read securables with columns), write/DDL checks (`authorize_statement`), the `krishiv::audit` denial record, `PathPrefixPolicy`
- `src/partitions.rs` partitioned and bucketed tables: the layout `CREATE TABLE` stores (partition columns last), the partitions the catalog tracks (`ADD PARTITION`, registered after `INSERT`/CTAS), `DESCRIBE ... PARTITION`, `SHOW PARTITIONS`, `ANALYZE ... PARTITION`; `tests/partitioned_tables.rs`
- `src/char_write.rs` the write side of `CHAR(n)` / `VARCHAR(n)` columns (trim trailing spaces to the limit, else `EXCEED_LIMIT_LENGTH`; off under `spark.sql.legacy.charVarcharAsString`; nested char types are refused) and `output_columns` (CTAS and views keep the declared type); `tests/char_varchar_write.rs`
- `src/result_cache.rs` the result cache of an engine runtime (`krishiv.resultCache.*`, off by default; design `design/P2-T094-result-cache.md`; design P2-E1 R6: sessions built alone share the process-wide store `global()`, a supplied runtime owns its own, `EngineRuntime::results`; `krishiv.resultCache.maxBytes` is a runtime key): `CacheKey` plus the identity of every permanent table read, a query over permanent catalog tables with no non-deterministic call is served from and stored into it at `DataFrame::execute_stream`; dropped by the relation cache's invalidation calls (`RelationCache::clear` / `invalidate_table`: REFRESH TABLE, CLEAR CACHE, engine writes) and by the TTL. Temporary views over permanent tables are inlined (eligible); in-memory tables, reads by path and plans that substituted a session-cached relation are not.
- `src/dataframe.rs` `DataFrameWriter` (files: `save`, `parquet`/`csv`/`json`/`text`; tables: `save_as_table`, `insert_into`; `bucket_by`/`sort_by`, which only Spark's `saveAsTable` takes and the engine has no bucketed tables for) and `DataFrameWriterV2` (`writeTo`). Table writers have no statement of their own: they run `table_commands.rs` `exec_save_as_table` / `exec_insert_into` / `exec_write_v2` (one path with `CREATE TABLE AS` and `INSERT`) and make the access checks of the statement they stand for through `authorize_equivalent` (`tests/access_policy.rs`). `saveAsTable` overwrite drops and recreates the table only after every check that can refuse the new one (`validate_new_table`, `Session::check_write_ready`, `UNSUPPORTED_OVERWRITE.TABLE`); `tests/dataframe_writer_tables.rs`
- `src/explain.rs` EXPLAIN and `DataFrame::estimate` (ADR 0041: estimated table-scan bytes and rows from the optimizer's statistics, `None` when unknown; the CLI's agent cost gate uses it); `src/profile.rs` profile for EXPLAIN ANALYZE
- `src/system.rs` the reserved `system` catalog (P2-T126): `system.<table>` with an empty namespace, rows built per query from process state (one split in-process); `system.capabilities`, `system.metrics` (the engine metrics snapshot: labels `MAP`, histogram `buckets` `ARRAY<STRUCT>`), `system.caches` (the file-metadata cache from `MetadataCache::stats()` and the relation cache), `system.operators` (one row per operator of a finished query, from its `QueryMetrics`), `system.queries` (the runtime's `QueryHistory` seen through the session's `QueryLog`: UUIDv7 or caller operation id, state, text, times, wall time, peak memory, error class; recorded around every query in `run_on_query`; the principal's own rows unless it holds `MONITOR` on `system`) and `system.memory` (the pool tree from `MemoryPool::snapshot()`, taken when the scan is planned) so far (`register_build_features` is how the binary lists its cargo features); `query_text` follows `krishiv.system.queryText.maxBytes` (default 4096, cut at a character boundary, `query_text_truncated`) and `krishiv.system.queryText.literals` (`keep`, or `mask`: `krishiv_sql::mask_literals`, every literal `?`), read from the session configuration when a statement is recorded (`TextPolicy`); `CREATE|DROP` of anything in `system` is `KRISHIV_RESERVED_NAME` (`access.rs`); `tests/system_tables.rs`
- `src/python_udfs.rs` the session's Python UDF registrations (P2-T059) and the encoded name of an unregistered UDF's call (`functions::python_udf_call`, a `session.`-qualified NUL-marked name `SessionFunctions::lookup` decodes before lower-casing; top-bit versions)
- `src/telemetry.rs` the `krishiv.query` span (OTel `db.*` attributes, sanitized text, `krishiv.session_id`/`query_id`) each action of a `Session::sql` frame runs in; `tests/tracing_spans.rs`
- `src/otlp.rs` (feature `telemetry-otlp`, off by default; owner decision 2026-11-04, ADR 0028 checklist in the PR): `OtlpTracing` (batch span exporter over OTLP/HTTP protobuf, `.layer()` for the `tracing` subscriber, `flush`), `encode_metrics` (pure: a `MetricsSnapshot` to an OTLP metrics request: cumulative sums, gauges with `worker_id`, explicit-bucket histograms with per-bucket counts) and `OtlpMetrics` (a thread that pushes `session.metrics()` every interval and once at drop; a failed push is logged, never fails a query). ## Writers (Spark 4.0 `DataFrameWriter` is the reference)
- `saveAsTable` modes: `errorifexists` fails on an existing table, `ignore` leaves it, `append` adds by column name (another format, a partitioning or other names are `KRISHIV_UNSUPPORTED_FEATURE`), `overwrite` drops and recreates. `insertInto` is by position: `append`, `ignore` and `errorifexists` all append, `overwrite` is `INSERT OVERWRITE`. The format defaults to `spark.sql.sources.default` when `format()` was not called.
- The file formats the engine writes are Parquet, CSV, JSON, Avro and text (one string column); `orc` writes are `KRISHIV_UNSUPPORTED_FEATURE`.

## Extension points
- New DataFrame action: an async method in `src/dataframe.rs` running on the session executor; transformations only build IR.
- New config key: add it to the typed registry in `krishiv-common` (see that crate's map).

## Invariants
- One pipeline: no API surface plans or runs queries any other way.
- Nothing a config doc calls process-wide is built per session: it lives on `EngineRuntime` (the 50-session test in `tests/runtime.rs` checks it).
- Each query reads a snapshot of the configuration; a concurrent `conf().set` never changes a running query.
- Transformations only build IR; actions are `async` and run on the session's executor, so they work from
  any runtime. Dropping an action's future or result stream cancels its query.
- SQL-bodied temporary functions live in a per-session map (`sql_functions.rs`) replaced on every change (never edited); a
  query takes the map when it starts and reads one snapshot, and every change bumps the registry version.
- The IR is reachable only behind the `unstable-ir` feature (not covered by semver).
- A read of a permanent view analyzes the view's query once on its own (`Session::check_stored_views`) before the whole query, so its binding mode can check types and names (`INCOMPATIBLE_VIEW_SCHEMA_CHANGE`, `CANNOT_UP_CAST_DATATYPE`); `TYPE EVOLUTION`/`EVOLUTION` views store their new schema only after the whole query analyzed, with a compare-and-swap (a concurrent change wins).
- Access control: one principal and one `AccessPolicy` per session, for life. Reads are checked in analysis; what a statement writes, creates or drops (`krishiv_sql::statement_targets`) is checked in `sql` before it is dispatched, and `df.write` paths before `DirectoryWrite::begin`, all through `krishiv_plan::analyzer::authorize` (fail closed, 42501, no reason, no existence oracle). Permanent views are inlined before binding, so `authorize_reads` asks the policy about every catalog-store lookup in plan order before any read (name as written and folded, then the view securable); a failure inside a stored view's text is raised only after that. The views read by the body of a SQL function a query calls are asked about after Bind (`authorize_body_reads`; the denial comes before the result or any failure in the view's text, but the tables inside the view are loaded first). Every denial logs one `krishiv::audit` record. Deny-all and inverse matrices: `tests/access_policy.rs` (merge-blocking).
- `#![forbid(unsafe_code)]`; no `unwrap`/`expect`/`panic` in library code; errors carry a Spark error class
  and SQLSTATE.
