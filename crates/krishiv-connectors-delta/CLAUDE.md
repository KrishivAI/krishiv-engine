# krishiv-connectors-delta

**Layer:** L5 (may depend only on crates in L5 or lower; `cargo xtask layering`).  
**Real code arrives:** P3.

## Purpose
Delta Lake connector on `delta_kernel` (no default features) with our own Engine implementation.

## Layout
- `src/error.rs` kernel errors as Krishiv errors (a Krishiv error raised in a handler travels through the kernel and back).
- `src/engine/schema.rs` kernel `StructType`/`DataType`/`Scalar` to Arrow 60 and back (µs timestamps, unshredded Variant, field ids).
- `src/engine/data.rs` `KrishivEngineData`: the kernel's `EngineData`/`GetData` over a `RecordBatch` (port of the kernel's `arrow_data` and `arrow_get_data` modules).
- `src/engine/mod.rs` `DeltaEngine`, the kernel's `Engine` (IoContext, StoreId, table root, tokio `Handle`, `DeltaLimits`, its cancellation: a token at planning, the running query's `QueryContext` for a scan via `DeltaEngine::for_query`) and `delta_blocking`, the only entry to kernel calls; `src/engine/pool.rs` `LogPool`, the one process-wide bounded pool of its own OS threads (`krishiv.delta.logThreads`; never the runtime's blocking pool, which the handlers' local I/O needs), cancellable slot wait, `delta.log_pool.wait_ms` (`WaitStats`), the log-pool thread flag the handlers' `block_on` asserts.
- `src/engine/storage.rs` `KrishivStorageHandler` (`list_from` via `IoContext::list_from`, `read_files` lazily per item with the `_last_checkpoint`/`.crc` limits, `put` with `put_if_absent`, `head`, `delete`; `copy_atomic` unsupported); `src/engine/json.rs` `KrishivJsonHandler` (arrow-json; `UTC` timestamps cross arrow-json as `+00:00` since chrono-tz is banned) and the parse limits (`KRISHIV_CATALOG_LIMIT_EXCEEDED`); `src/engine/paths.rs` `TableRoot`, every URL confined to the table root (lexically, and on local roots also with symlinks resolved).
- `src/engine/columnar.rs` `KrishivParquetHandler` (the kernel's ParquetHandler; the format comes from `FormatRegistry`, never named) over krishiv-io's `ScanStream`/`ParquetFormat` (checkpoints, sidecars, `stats_parsed`, CDF): lazy per-file reads, one batch per pull with cancellation checked before each, the footer length checked against `krishiv.catalog.maxMetadataBytes`, columns by field id then name at every struct level, reader widenings, `row_index`/`_file`; `write_parquet_file` one overwriting put returning the size (the whole file is buffered outside any reservation: used for checkpoints only; data files stream through `write/files.rs`); reads versioned by the store's `head` (ETag/mtime); `read_parquet_footer` with field ids.
- `src/engine/eval/` `KrishivEvaluationHandler`, the kernel's evaluator over Arrow compute (port of the kernel's `arrow_expression`): `expr.rs` expressions (checked arithmetic, safe casts, `Coalesce`, `Struct`, `StructPatch`, `Array`), `predicate.rs` (NOT pushed down, Kleene AND/OR, null-safe `DISTINCT`, `IN` never NULL; `Unknown`/`Opaque` unsupported), `json.rs` `ParseJson` (bad timestamp/date/decimal cells NULL, an unparseable batch NULL) and `ToJson` (ms, `Z`), `partition.rs` `MapToStruct` (Delta's partition-value encoding), `types.rs` the type check and output conformance; `src/engine/relabel.rs` zone/name relabelling without copies (`UTC` crosses Arrow as `+00:00`).
- `src/features.rs` Krishiv's reader allow-list (design §3.5–3.7) on a `ReadProtocol` (protocol + configuration): unsupported reader features → `DELTA_UNSUPPORTED_FEATURES_FOR_READ` (delta-spark's parameters, `Krishiv <version>`); catalog-managed, coordinated commits (writer feature or `delta.coordinatedCommits.*`) and row-tracking columns → `UNSUPPORTED_FEATURE.TABLE_OPERATION`; `snapshot_error` maps the kernel's own refusals (`MaxCatalogVersion`, "Feature 'x' is not supported") the same way. Tests `src/features/tests.rs` (every row on edited protocols; delta-spark's probe `PROBE-unknown-reader-feature.json`).
- `src/table/mod.rs` `DeltaTable`, the `TableProvider` of one table at one version (`open`/`open_with(engine, Option<u64>, config)`, the pinned version is the time-travel hook; `hadoop_path` is delta-spark's `file:/…` form of `<tableNameOrPath>` for a path table, a catalog table passes its name); `src/table/cache.rs` `SnapshotCache`, the cross-query snapshot cache (ADR 0037; key: root, `StoreId`, credential identity; bounded by count and by estimated bytes, `krishiv.delta.snapshotCache.maxBytes`, a listing over the bound not kept; a hit is checked with one `head` of its last commit file, then brought up to date from the cached snapshot; any failure drops the entry and rebuilds): snapshot on the log pool, the allow-list before the listing, engine Arrow schema (column-mapping metadata kept), `ScanUnit` per live file, statistics = `numRecords` less DV cardinality, `scan_units` = files; kernel-parsed partition values (`partition_scalar`). `src/table/predicate.rs` pushed filters as a conservative kernel `Predicate` (comparisons, IS NULL, IN, AND/OR/NOT; exact types only, no floats or collations). `src/table/scan.rs` `DeltaScan` (`ScanPushdown`: Inexact/Unsupported, the predicate recorded on the source) and `DeltaScanSource` (a pushed predicate re-lists through the kernel once per run; one unit per file through `ScanStream` with `FieldMapping::DeltaColumnMapping`, partition columns from the log, DVs via `DvInfo::get_row_indexes` on the log pool as a `RowSelection`, charged to the driver's reservation; runtime filters applied last to each batch through krishiv-exec's `RuntimeFilters::source_rows`; every kernel call of a run on the engine bound to the query's cancellation).
- `src/commit/` (PR-37a, design §4.2 and §5) `commit` (`run.rs`): the commit loop over `StagedCommit` (add rows, removed scan rows, the `ReadSet`), one kernel transaction per attempt on the log pool with `commitInfo.tags."krishiv.writeId"`, `isolationLevel`, `readVersion`; `Conflicted` reads the winners (`winner.rs`, size and depth limits) and either finds its own write id (landed) or checks each (`conflict.rs`, delta-spark's `ConflictChecker` at Serializable: protocol, strict metadata, domains, app ids, append by partition predicate through the evaluator, delete-read, delete-delete; Delta's classes, hints and parameters), then rebuilds at the last checked version; `Retryable`/`Err` run the landed check first; `RetryLimits` (Delta's `maxCommitAttempts`, a time bound, jittered backoff). `src/features.rs` also holds the writer allow-list (`check_write` on a `WriteProtocol`; `check_create` on the features a create's properties and schema make the kernel's create enable, run first in `plan_create`). Tests `src/commit/tests.rs` on a copy of the `partitioned` oracle table (`delta_conflict_matrix`, `delta_commit_response_lost`, `delta_rebuild_at_checked_version`).
- `src/write/` (PR-37a part 2, design §4) the write path: `sink.rs` `DeltaWriteSink` (`DeltaTable::writer`/`writer_with`: Append, Truncate, OverwriteByFilter on partition columns, OverwriteDynamic; the allow-list, `DELTA_CANNOT_MODIFY_APPEND_ONLY` and the CDF overwrite refusal before any file; the write's kernel transaction built once on the log pool by the first driver that needs it (`Planned`); each driver's `DriverWriter` behind an async mutex, its reservation from the driver's own consumer (`NeedMemory` grants land there), the batch written in a `Blocked` future, `spill` = encode and ship the buffered row groups (a spill that finds the writer busy sets `flush_wanted`, and the batch's future flushes when it ends); the driver's seat in the `delta-write` cohort holds while a batch is written and while `combine`'s background flush (`release_combined`, the ended driver's row groups shipped) runs, so another driver's arbitration round waits for those bytes instead of failing; at finalize the drivers' files ended, the removes from the scan metadata re-checked exactly against the predicate (`ExactCheck`, only TRUE removes, refuse when not evaluable), Delta's `WRITE` parameters and metrics, the commit loop, a detached checkpoint past `delta.checkpointInterval`, failures counted by `checkpoint_failures`; a failure before the commit deletes the files) and `NewDeltaTable` (CTAS/new table: version 0 in one `create_table` commit carrying the write id; a build failure or `Conflicted` reads version 0, this write's id there = landed, else `TABLE_OR_VIEW_ALREADY_EXISTS`; `create_empty`); `files.rs` `DriverWriter`: rows grouped by partition (`arrow_row` keys per batch), one open file per partition streamed through the Parquet encoder into a multipart upload, rolled at `maxRecordsPerFile` and 128 MiB, each partition bound once (kernel `logical_to_physical`: physical names, field ids), add rows; before grouping, empty string/binary partition values become NULL (`null_empty_partition_values`, what the kernel stores; a NOT NULL partition column is checked again after it, so `''` there is `DELTA_NOT_NULL_CONSTRAINT_VIOLATED`) and `conform` raises `DELTA_NOT_NULL_CONSTRAINT_VIOLATED` for a NULL at a non-nullable path, nested struct fields included (`check_not_null`, on the incoming column before any cast); `stats.rs` Krishiv's stats on the kernel's `stats_schema`, accumulated per file over its batches (`StatsAccumulator`; the min cut by code points, the max by delta-spark's UTF-16 rule, NaN as `"NaN"`, -0.0 as 0.0, `tightBounds` with DVs only); `filter.rs` an overwrite filter as a partition-column kernel predicate (data columns refused), checked against each written batch (`DELTA_REPLACE_WHERE_MISMATCH`). `READS_TARGET_OPTION` / `PREDICATE_TEXT_OPTION` are the session's write options. `RetryLimits::from_config` (`krishiv.delta.maxCommitAttempts` = `spark.databricks.delta.maxCommitAttempts`, `krishiv.write.commitRetryTimeout`). Tests `src/write/tests.rs` against `write-stats/`, `WRITES.json`, `WRITE-EDGES.json` (empty partition values, NOT NULL, `maxRecordsPerFile`; `gen_delta_fixtures.py /out edges`), `write-features/` (`delta_stats_match_spark`, `write_modes_match_oracle`, `delta_write_allowed_features`, `delta_write_refusals`, column mapping field ids at every level); `src/write/tests/streaming.rs` (a write larger than the pool, the memory class, exact removes with NULL/int/date partitions, the create's landed check, a failed write leaves no files, the checkpoint, `delta_no_internal_error_on_oracle_tables`); `src/write/tests/lifecycle.rs` (cancel during the batches and during finalize, the global state dropped (`test_hooks.rs`, `cfg(test)` hooks by write id), one checkpoint per root, a scan row without partition values refused); `src/write/tests/readback.rs` (Spark reads Krishiv-written tables: `tests/fixtures/delta-4.4.1/krishiv-written/`, written by the ignored `write_readback_tables` with `KRISHIV_DELTA_READBACK_OUT`, read by `gen_delta_fixtures.py /out readback /in` into `READBACK.json`; `spark_reads_krishiv_written_tables`, field ids through arrays and maps).
- `src/write/dml.rs` (PR-37b part 2, design §2.3, §6.1-6.2) `DeltaRowLevel`, the `RowLevelTable` of `DeltaTable::row_level(Delete | Update)` (copy-on-write only; `MERGE` is PR-37c): `scan`/`scan_files` are `RowIdScan`s over a `DeltaScan` with row ids (`_krishiv_row_file` = the path the log names, `_krishiv_row_index` = the decoder's row index, deletion vectors applied; `DeltaTable::row_level_scan`), refusing first by the writer allow-list and `DELTA_CANNOT_MODIFY_APPEND_ONLY`; `rewriter` is the write sink in `Mode::RowLevel` (`sink::row_level_sink`): a `DELETE` without a condition or with a partition-only one (`filter::partition_predicate` of the request's `read_filter`; a column one-part or qualified by `ROW_LEVEL_ALIAS_OPTION`, never a struct field `s.p`; a string against a `TIMESTAMP` column refused) is whole-file when it wrote no row (the touched files, plus untouched files of the matching partitions only when their statistics prove no live row, any live file without a condition: the find query, never the translation, decides what goes; `numDeletedRows` from `numRecords` less DV cardinality, `-1` result when unknown), else the touched files are removed (scan rows with their DVs) and the rewritten rows added; on a change-data-feed table `UPDATE` and a row `DELETE` are `UNSUPPORTED_FEATURE.TABLE_OPERATION` before any file; commit `DELETE`/`UPDATE` with delta-spark's metrics, the predicate as written (`["true"]`/`[]` without one), the read set = the condition's partition conjuncts (`filter::partition_conjuncts`; the whole table when the request has no `read_filter` (no condition, or the session's rule: a subquery or view that reads the target again, compared by resolved table root, krishiv-session `catalog/scans.rs` `reads_delta_root`) or the filter holds a subquery (`dml::has_subquery`)) and as read files the removed files plus every live file the read predicate selects (delta-spark's candidate files); the listing keeps only the scan-metadata batches holding a removed file (`sink::for_each_scan_batch`); nothing changed = no commit; `output` = `num_affected_rows`. The session passes the find query's count, condition text and time as `ROW_LEVEL_*_OPTION`s. Tests `src/write/tests/dml.rs` (row ids past DVs, removes and metrics, whole-file delete, an untouched live file never removed, a whole-file plan that wrote rows commits a rewrite, `s.p`, no-op, delete-read and append conflicts, appends inside and outside the partitions read, cancel during the rewrite, a failure while staging (`test_hooks::fail`), refusals); the oracle comparison is krishiv-session `tests/delta_dml.rs` against `tests/fixtures/delta-4.4.1/dml/DML.json`.

## Not here yet (PR-08b part 2 left these; time travel waits for PB-07 `TableVersionSpec`, CDF read is PR-37e)
- Time travel and `@`: `DeltaTable::open_with` already takes a pinned version.
- CDF read (`table_changes`, `readChangeFeed`).
- Delta row-tracking columns: `features::row_tracking_refused` is wired once `MetadataCols` can name them.
- The pushed predicate prunes files only (not row groups: no `ScanRequest::predicate`).
- A catalog table whose log schema changed since it was registered is refused by the session (delta-spark reads
  the snapshot's schema on every query).
- Arrays and maps under column mapping, `NOT NULL` columns (the analyzer makes file columns nullable) and inline DVs
  have no oracle table.
- Writes: `variantType` stays off the writer allow-list (no Variant round trip yet); a `replaceWhere` on data
  columns (delta-spark rewrites the matching files' other rows); schema evolution on write (`mergeSchema`); a
  `krishiv.delta.*` key for the target file size; the CRC after a commit; a `krishiv.delta.checkpointTimeout`
  key (the checkpoint's budget is a constant 600 s, one per table root at a time); `numDeletedRows` of a
  `replaceWhere`; a file's raw stats rows (up to 64, uncut string bounds per column) are outside the
  driver's reservation; NOT NULL fields inside arrays and maps are checked only by Arrow's own validation. A cancelled write's files (during its batches or `finalize`, up to the commit attempt) are
  deleted in the background; from the commit attempt on they stay (the outcome may be a landed commit).
- DML: `MERGE` (PR-37c); deletion vectors are never written (merge-on-read, PR-37d: delta-spark marks rows in DVs
  on a DV table by default, Krishiv rewrites); a whole-file `DELETE` is recognised only for conditions
  `filter::partition_predicate` translates; the read set's partition conjuncts likewise (others widen it to the whole
  table).
- A commit that is not a blind append (DELETE, UPDATE, MERGE, overwrite) has no `isBlindAppend` in its commitInfo, where delta-spark writes `false`: delta_kernel 0.30.1 replaces the connector's value and writes the field only when true, so `DESCRIBE HISTORY` in Spark shows NULL (found by PR-53b's round trip, which pins it).
- A landed check after the query is cancelled cannot run on the log pool: it raises `OPERATION_CANCELED` and the
  outcome is unknown.

## Invariants
- `delta_kernel` with `default-features = false`; never `deltalake`.
- On a `delta_kernel` upgrade, compare `features.rs` `CREATE_FEATURES` and `check_create` with the kernel's
  `ALLOWED_DELTA_FEATURES` and its create's auto-enable steps (`transaction/builder/create_table.rs`): they are a
  hand copy, and a feature the new kernel admits would otherwise pass the create unseen.
- Kernel calls run only through `DeltaEngine::delta_blocking` (the log pool), never on a runtime worker (the writer's per-batch work is Krishiv's own evaluator and encoder, and the pure `BoundWriteContext` accessors; binding a partition goes through the pool); lazy kernel iterators are drained inside that call; puts are never raced against cancellation once started (`block_on_to_completion`); every handler call checks the query's cancellation first and confines its URLs to the table root.
- `#![forbid(unsafe_code)]`.
- No `unwrap`/`expect`/`panic` in library code; errors carry a Spark error class + SQLSTATE.
