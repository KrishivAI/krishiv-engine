# Krishiv 0.3.0

Krishiv 0.3.0 adds a server. `krishiv server` serves Spark Connect, Arrow Flight SQL and a web console from one process,
so stock PySpark, JDBC and ADBC clients can connect without a JVM on the server side (the Arrow JDBC driver itself needs a Java runtime on the client). The embedded engine from 0.2 is still there. If you are
moving from 0.2, read [Upgrading from 0.2](../guides/upgrading-from-0.2.md) first. The complete list of changes is in the
[changelog](https://github.com/KrishivAI/krishiv-engine/blob/main/CHANGELOG.md).

## Highlights

- **A Spark Connect server.** `krishiv server` answers Spark Connect from a stock PySpark client
  (`pip install pyspark-client`): queries, DataFrame writes, `spark.catalog`, caching, artifacts, reattachable results and
  interrupts. `krishiv.start_local()` starts one in your own process on a free loopback port. Spark 4.3 is now the
  default Spark profile.
- **Arrow Flight SQL.** In the Docker image the same port serves Flight SQL, so ADBC and Arrow JDBC drivers run statements and prepared
  statements. See [Arrow Flight SQL](../guides/flight-sql.md).
- **Lakehouse tables** (Docker image; the wheels and release binary do not include them, see [What each artifact includes](../get-started/install.md#what-each-artifact-includes)). Read Delta Lake and Iceberg tables, including deletion vectors and row-level deletes. Write Delta tables
  with `INSERT`, `INSERT OVERWRITE`, `DELETE`, `UPDATE` and `MERGE`, with each format's conflict rules. Iceberg REST
  catalogs can be declared and read (Iceberg is read-only; writes are Delta), with vended credentials and per-user delegated authentication. See
  [Lakehouse tables](../guides/lakehouse-tables.md) and [Delta DML and MERGE](../guides/delta-dml.md).
- **Security and access control.** TLS, client certificates and OIDC tokens; `GRANT`, `REVOKE` and roles checked per
  column; confined file paths; trusted impersonation for a front end acting for a user. See
  [Securing a single-node server](../guides/single-node-server-security.md) and
  [Access control](../guides/access-control.md).
- **Python UDFs in worker processes.** Scalar, pandas, Arrow, grouped, cogrouped, window and table-function UDFs run in
  sandboxed worker processes, kept apart per tenant. See [Python UDF sandbox](../guides/python-udf-sandbox.md).
- **Operate it.** Workload management with resource groups, draining on SIGTERM, an admin API, `krishiv doctor`, query
  history with partition advice, and a console with catalog, SQL editor, sessions and plan pages.
- **More Spark.** Many Spark 4.3 functions and syntax (`ASOF JOIN`, `TIME`, metric views, `JSON_TABLE`), the Python Data
  Source API, Avro and Protobuf functions, and a golden-test pass rate of about 90% against Spark 4.3.0.

## Installing

See [Install](../get-started/install.md): `pip install krishiv`, the Docker image, the `krishiv` CLI binaries and
`cargo install krishiv-cli`.

## Known limits

<!-- RELEASE-DAY: confirm the scope statement for streaming, incremental views and distributed execution (0.2 said they were not included). -->
- Iceberg tables are read-only: no `INSERT`, `DELETE`, `UPDATE` or `MERGE` reaches one. Write Delta or Parquet instead.
- Settings that stand for a JVM or a cluster (`sparkContext`, RDDs, `enableHiveSupport`, the JDBC reader and writer) are
  not supported. They raise `KRISHIV_UNSUPPORTED_FEATURE`; the `sparkContext` message names the DataFrame way. See
  [Migrating from PySpark](../guides/pyspark-migration.md).
- About 10% of the Spark 4.3.0 golden cases still differ; they are recorded as known failures in the repository.
- The APIs are not stable before 1.0.
