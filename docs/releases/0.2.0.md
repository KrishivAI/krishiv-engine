# Krishiv 0.2.0

Krishiv 0.2.0 is the embedded core: the engine runs in your process, from Python or Rust. The complete list of
changes is in the [changelog](https://github.com/KrishivAI/krishiv-engine/blob/main/CHANGELOG.md).

## Highlights

- **Embedded Spark-compatible engine.** `krishiv.session()` gives a PySpark-style session in your process, from Python
  or Rust, with no JVM. Spark-observable behaviour is checked against real Spark runs.
- **Memory-bounded and fast.** A vectorized Arrow executor spills aggregation, joins, sorts and window frames to disk
  instead of failing. It has runtime filters, Parquet row-group and dictionary pruning, and a cost-based join order.
- **Broad SQL.** Windows (`ROWS` and `RANGE`), `GROUPING SETS`, lateral joins, recursive CTEs, SQL scripting,
  `CHAR` and `VARCHAR`, collations, `VARIANT`, calendar intervals, `GEOMETRY` and `GEOGRAPHY`, `PIVOT`,
  `TABLESAMPLE`, SQL functions and `IDENTIFIER(..)`.
- **Python UDFs in process.** `@udf`, scalar `pandas_udf` and `arrow_udf` run on a thread pool, in parallel on
  free-threaded Python 3.14t.
- **See what happened.** `EXPLAIN [ANALYZE | COST | VERBOSE]`, a versioned JSON profile with per-scan I/O, a local
  web console, Prometheus metrics, OTLP spans and JSON logs. Errors show the SQL span that raised them.
- **Zero-copy interop** with pyarrow, Polars and DuckDB through the Arrow PyCapsule interface.

## Installing

- Python 3.11 or newer: `pip install "krishiv[pyarrow]"`. See the [Quickstart](../get-started/quickstart.md).
- Rust: the `krishiv` crate is not on crates.io yet; build it from the repository. See
  [Native Rust UDFs](../reference/rust-udfs.md) for the UDF API.
- Command line: `krishiv sql` is the SQL shell. Build the `krishiv-cli` crate from the repository to get it. See
  [Run SQL from the command line](../guides/run-sql-from-the-command-line.md).

## Known limits

- Temporary views over in-memory DataFrames, and SQL expression strings (`selectExpr`, `expr`), are not supported
  yet. Read data from files for views.
- Spark Connect, streaming, incremental views and distributed execution are not part of this release.
- The APIs are not stable.
