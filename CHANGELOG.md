# Changelog

All notable changes to Krishiv are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project follows
[Semantic Versioning](https://semver.org/) once it reaches `1.0`; until then, any release may change its public API.

Later entries are generated by release-plz from Conventional Commits (`release-plz.toml`) and edited by hand.

## Unreleased

## 0.3.0

### Added

- Python UDF workers of `krishiv server` can run in an OS sandbox (Landlock, seccomp and resource limits; no root needed): no network, no other programs, and no files outside the allowed paths. `krishiv.udf.sandbox` (default `on`) refuses server-side Python UDFs when the kernel cannot enforce it. (#717)
- Setting `krishiv.history.path` now records every finished query's profile as a bounded Parquet history you can query later. (#719)
- The Iceberg connector reads a table's schema, snapshots and manifests from its metadata file, with every file access going through Krishiv's own storage layer (its retries, request limits and caching apply). (#722)
- The built-in catalog can now be driven through catalog-level calls (create, alter and drop namespaces and tables); a schema change with several steps applies all or none of them. Not yet reachable from SQL, and renaming a table is not supported through it. (#726)
- The Delta Lake connector evaluates Delta log expressions itself (file statistics, partition values and data skipping), checks query cancellation throughout, and reads a struct column by field name. (#728)
- Collation names backed by ICU (for example `UNICODE`, `UNICODE_CI`, `fr_CI_AI`) now compare, sort, and `upper`/`lower` as Spark does; the `collations-icu` feature is on by default and adds about 1.70 the binary. (#729)
- `krishiv server` can serve TLS, require client certificates (mTLS) and accept OIDC bearer tokens. With authentication on, reads and writes by path are confined to `krishiv.io.local.allowedRoots` and `krishiv.io.objectStore.allowedPrefixes`, and server-wide store options need the admin role. (#733)
- `krishiv server` answers Spark Connect's AnalyzePlan, Config and Interrupt requests, so a stock PySpark Connect (#738)
  client can read schemas and explain plans, get and set session configuration, and interrupt running operations.
- The documentation has an overview page for every section, a description on each page, a Single-node deployment section, and workarounds for more unsupported Spark functions in the PySpark migration guide. (#740)
- `krishiv server` keeps a reattachable Spark Connect query's recent results, so a client whose connection drops (#742)
  resumes the result stream where it stopped instead of failing; released or long-detached queries free their memory.
- The Delta Lake connector reads Delta tables: deletion vectors, column mapping by name and by id, type widening, partition pruning and data skipping. Tables with reader features Krishiv does not support, and catalog-managed tables, are refused with Delta's error classes. (#744)
- Embedded sessions get `spark.catalog`: list and look up databases, tables, columns and functions, create and cache tables, and drop temporary views, with the same access checks as the matching SQL statements. (#745)
- The engine can plan and run grouped, cogrouped and map-style Python UDFs and Python aggregate UDFs (the `mapInPandas`, `applyInPandas`, `cogroup` and grouped-aggregate kinds) over a UDF runtime; plans that contain them carry the new plan-codec feature `python_udf_relations`. The runtimes that execute them follow in later releases. (#746)
- Groundwork for reading tables from a Hive metastore: location checks for what a catalog returns, and a bounded, read-only metastore client. Not yet reachable from SQL. (#747)
- Workload management: `krishiv.workload.resourceGroups.file` limits concurrency, queueing, per-query memory and scanned bytes per group, routes queries by user, source, tag and statement type, and the lowest-priority query is stopped first when memory runs out; `system.queries` shows each query's `resource_group` and `queued_ns`. Queries can carry request tags and be cancelled by tag (`Session::interrupt_tag`, `EngineRuntime::cancel_by_tag`). (#748)
- (RS-15) The `krishiv` and `krishiv-cli` crates now have a `telemetry-otlp` feature that forwards to `krishiv-session/telemetry-otlp`, so the OTLP code in the session crate can be built in through them; 0.2.0 named the feature in the changelog but only `krishiv-session` had it. The CLI does not install an exporter by itself yet. (#751)
- Query analysis now records which views a query read and how each was expanded (invoker, definer or temporary), the groundwork for column lineage in the analyze API. (#753)
- The Get started page of the documentation now holds the quickstart, and every generated reference page (SQL functions, Python, Rust, configuration, metrics, Spark Connect coverage) carries a description. (#754)
- `krishiv server` can run scalar Python UDFs (`@udf`, scalar `pandas_udf` and `arrow_udf`) in a pool of separate, sandboxed Python worker processes, one per principal and session, configured by `krishiv.python.worker.*` and `krishiv.udf.sandbox`. (#755)
- Observations (DataFrame.observe, Observation) are supported: metrics are computed in the query's own plan. (#756)
- A catalog can rename a table within its namespace as one swap of its entry, and a shared contract suite checks every catalog's write half; the commit log can list the files of one exact version. (#758)
- The Python `pyspark.sql.functions` names that were missing now exist with PySpark's signatures: the generators (`explode`, `posexplode`, `inline`, `stack`, ...), the higher-order functions (`transform`, `filter`, `aggregate`, `exists`, `forall`, `zip_with`, `map_filter`, `transform_keys`/`transform_values`, `array_sort` with a comparator, ... take Python lambdas), `max_by`/`min_by`, `any_value`, `array_agg`, `every`/`some`, `chr`, `power`, `negate`, `like`/`ilike`/`rlike`, the CSV and XML functions with options, the sort-order, bitmap, sketch and `xpath` families, `broadcast` and `call_udf`; `Column` gains `**`. A function the engine lacks raises a clear `NotImplementedError` or `UnsupportedOperationException` when called, never an `AttributeError`; `random` is added too. (#765)
- `Session::analyze` (Rust) returns what a statement needs and produces without running it: its class (READ, WRITE, DDL, SESSION, ADMIN), the securables it reads and their columns, its output schema and per-column lineage (source tables and columns, the transform, filter columns), as the versioned JSON document `krishiv.analyze.v1` (schema in the reference docs). (#766)
- `krishiv server` authenticates every Spark Connect RPC once authentication is configured (static tokens, client certificates or OIDC): each session belongs to its caller, Connect requests follow the viewer/operator/admin role matrix, both ports serve TLS, and refusals are counted on `/metrics` (`krishiv_auth_failed_total`, `krishiv_auth_denied_total`). (#769)
- Spark Connect group 1 has the IR it needs: nested literal values, a declared schema on file reads and a data-carrying local relation, each with a plan codec feature (PR-12 part 2a, #772). (#772)
- Spark Connect translates local relations, declared file schemas, qualified subquery aliases, nested literals, expression strings and `spark.sql()` (sql_command), as part of group 1 (PR-12 part 2b, #774). (#774)
- Delta tables can be used from the session (build feature `delta`): `spark.read.format("delta").load(path)`, `` delta.`path` ``, `CREATE TABLE .. USING delta LOCATION` and the temporary-view form. Writes and DDL on Delta tables are refused by name for now. Snapshots are cached per table root (`krishiv.delta.snapshotCache.maxBytes`, 64 MiB), and a cancelled query stops its Delta work. (#782)
- Tables whose provider offers a row-level table can now run `DELETE` and `UPDATE` (copy-on-write: the touched files are found, then rewritten and committed once). No built-in table offers one yet: the Delta and Iceberg connectors wire in next. Plans gain a `TableWrite` node (plan codec feature `table_write`) that writes a query's rows into a table provider. (#784)
- The `krishiv-session` library gains service principals with trusted impersonation: a principal table (`krishiv.auth.principals.<name>.privileges|impersonates|expires`, names may contain dots), signed act-as assertions, and `ServerAuth::impersonate` / `impersonate_signed`, by which a service such as a portal acts for an end user. The end user's role is capped at the service's, `expires` ends a principal's rights for every login method (a static service token needs one), and act-as never crosses tenants. Every refusal is audited and counted; `system.sessions` and `system.queries` show who acted for whom (`delegated_by`). `krishiv server` also hardens JWT logins (a lifetime cap, a required `exp`, the token id in the audit record, tokens carrying `act` refused as logins). The Connect transport that reads the `x-krishiv-act-as-*` headers arrives in a later PR; until then nothing on the wire calls the new APIs. (#785)
- Krishiv reads Iceberg REST catalogs with its own client (feature `iceberg-rest` of `krishiv-catalogs`): `/v1/config`, (#788)
  namespaces, tables, `loadTable` and `loadCredentials`, with a static bearer token or OAuth2 client credentials, the
  OneLake endpoint form, and hostile-server limits (no redirects, a capped body, one deadline per call, checked locations).
- On `krishiv server`, a viewer can `AnalyzePlan` a table it may not read: it gets the schema, tree string, flags and semantic hash, and its `explain` shows the plan with statistics and data withheld. Reads by path still need `Select`, a view's text is shown only to callers who may read the view, and every refusal is audited. (#790)
- Iceberg tables can be read: Krishiv plans the scan itself (the current snapshot, a snapshot id, a branch or tag, or `TIMESTAMP AS OF`), prunes data files by the table's column statistics and partition values, and reads append-only tables through its Parquet reader. (#791)
- - `EXPLAIN FORMAT JSON <statement>` returns the statement's analysis as JSON without running it. (#799)
- SQL access control for server mode: `GRANT`, `REVOKE`, `SHOW GRANTS` and roles, checked per column a query reads (`krishiv.access.provider=grants`). In server mode, outbound object-store and catalog requests reach only public addresses unless an admin allows more (`krishiv.io.egress.*`), and catalogs are declared at startup with `krishiv.catalog.<name>.*`. (#803)
- A float or double vector stored as a fixed-size list (up to 65,536 values, design P3-T075) now keeps its length through tables, Parquet and the plan codec, while expressions, UDFs and results see Spark's `array<float>` / `array<double>`. A Parquet column stored as a fixed-size list reads as `array<float>` through a table. (#804)
- SQL `window()`, `session_window()` and `window_time()`, and the `histogram_numeric(col, nb)` aggregate (Spark's `NumericHistogram`; its bins depend on where partial histograms merge, see known differences). (#805)
- Iceberg tables with deletes now read correctly: position delete files, deletion vectors and equality deletes written by Spark's merge-on-read DELETE, UPDATE and MERGE are applied, and data files without field ids are read through the table's name mapping. (#807)
- The bench harness has a `krishiv-connect` engine that starts `krishiv server` on loopback and runs TPC-H, TPC-DS and ClickBench through Spark Connect, so the server path is measured next to the embedded engine. (#808)
- `krishiv server` serves the `krishiv.admin.v1` control API on the admin listener over gRPC and REST (`/api/admin/v1`): `GetVersion` and `GetCapabilities`, behind the server's authentication, with `krishiv.server.allowedHosts` for loopback listeners. `GET /api/v1/version` is deprecated in favour of it and, with authentication configured, now needs a credential like `GetVersion` (P3-T066). (#809)
- Spark Connect: clients can upload artifacts (`spark.addArtifacts`, cached local data), with per-session and (#810)
  server-wide quotas, and read the full details of an error (`FetchErrorDetails`). `CloneSession` copies a session
  (configuration, temporary views and functions, variables, artifacts) under a new id, and `GetStatus` reports the
  state of a session's operations, including those that ended in the last 30 minutes.
- `from_avro` and `to_avro` read and write Avro datums for the scalar, array, map and record types Spark maps, with `mode` (PERMISSIVE, FAILFAST) and a literal options map, and `is_valid_variant` tells whether bytes are a well-formed variant (P3-T087, T088). (#811)
- Python UDFs over Spark Connect: `spark.udf.register` and inline `udf(...)` calls (scalar eval types 100, 101, 200 and 250) run on the server's isolated Python worker pool, in workers of the calling session only. Client code needs `Usage` on `System("udf")` (admin in server mode) before anything is registered or any worker starts; a UDF that raises reaches the client as `PYTHON_EXCEPTION` (PySpark's `PythonException`), and releasing a session stops its workers. (#813)
- A write of NULL into a NOT NULL column now fails with `NOT_NULL_ASSERT_VIOLATION`, as in Spark 4.2 (skipped under `spark.sql.storeAssignmentPolicy=LEGACY`). `krishiv-catalogs` has an embedded SQLite catalog behind the new `sqlite` feature (off by default): a catalog in one file that several processes can share, with the same behaviour as the in-memory one. (#814)
- The console gains a catalog browser, a SQL editor with run and cancel, and an environment page that shows secrets as `***`; `krishiv ui --profiles <dir>` opens stored profiles without a server. (#815)
- Iceberg scans read delete files only for the data files they actually read after filter pruning, charge that memory to the query, and skip equality deletes that column metrics rule out. `EXPLAIN` shows an Iceberg scan's snapshot, data files read and delete files by kind; table statistics come from the manifests; decoded manifests are cached (`krishiv.iceberg.manifestCache.bytes`, default 64MB). (#816)
- Python relation UDF kinds (map, grouped map, cogrouped map and grouped aggregate) run end to end in the sandboxed pool workers of `krishiv server`, with per-session and global worker-slot limits (`krishiv.python.worker.maxPerSession`, `krishiv.python.worker.maxTotal`). (#820)
- - `analyze` and `EXPLAIN FORMAT JSON` now list the table directory a run of `DROP TABLE`, `TRUNCATE TABLE` or `INSERT` also needs (`MODIFY`, and `CREATE` for `INSERT`), and give an `INSERT ... SELECT`, `INSERT OVERWRITE` or `CREATE TABLE ... AS SELECT` the output schema and column lineage of its query. (#821)
- Azure paths reach Microsoft OneLake (Fabric hosts) and take Hadoop ABFS credential keys (shared key, SAS, OAuth client credentials, workload identity, managed identity, a bearer token); explicit credentials no longer read ambient `AZURE_*` variables, and Azure store ids keep their host so printed paths re-parse. (#823)
- Trusted impersonation on the Spark Connect listener: a service such as a front end can act for an end user with `x-krishiv-act-as-*` metadata or a signed act-as assertion when the server grants it `impersonate`; every refusal is audited. (#827)
- The optimizer can group an aggregate by a fact table's join key and join the dimension's columns above it, when the dimension's key is known to be unique. With `krishiv.optimizer.discoverKeys` the session proves the key of plain Parquet files by reading the key columns once (bounded by `krishiv.optimizer.discoverKeys.timeout`) and caches the answer per file version. Both `krishiv.optimizer.payloadAboveAggregate` and `krishiv.optimizer.discoverKeys` are on by default (TPC-H q10 at SF1000: 196 s to 116 s, peak memory 20.2 to 8.1 GiB). (#829)
- `krishiv.start_local()` starts an in-process Spark Connect server on a free loopback port, guarded by a token made for each start, and returns the connection string for a stock `pyspark-client`. (#830)
- Spark Connect plans with `mapInPandas`/`mapInArrow`, `groupBy().applyInPandas`/`applyInArrow` and `cogroup().applyInPandas`/`applyInArrow` now translate into the engine's Python UDF relations (with the same `Usage` on `System("udf")` check as inline UDFs), so `df.schema` and `explain` work, and a grouped or cogrouped map over a nondeterministic UDF fails there with Spark's `INVALID_NON_DETERMINISTIC_EXPRESSIONS`. Running them still fails with `KRISHIV_UDF_NOT_AVAILABLE`: the UDF worker pool cannot run these relations yet. (#831)
- Partition advice: with `krishiv.history.path` set, `EXPLAIN` of a query that reads a table prints a `partition advice` line naming the column the recorded queries filtered on most that would prune the most bytes if the table were partitioned by it, and `system.partition_advice` lists the ranked suggestions of every table (read-only; no table is changed). - Iceberg write, part 1: a write task writes Parquet data files with the table's field ids, partition directories, rollover and column metrics (at most 100 open files a task), and an append's manifests, manifest list and snapshot are built as Java's FastAppend does. - The admin API `krishiv.admin.v1` can list and end sessions and queries (`ListSessions`, `KillSession`, `ListQueries`, `CancelQuery`, `CancelQueriesByTag`) over REST and gRPC. - Spark Connect clients can run `mapInPandas`, `mapInArrow`, `applyInPandas`, `applyInArrow` and cogrouped `applyInPandas`/`applyInArrow` on `krishiv server`. (#842)
- Iceberg write, part 2: appends commit through a loop that never retries blind. An unknown answer is checked against the table, and only the same attempt is resent, or the write is rebased once the branch has moved. A write whose outcome stays unknown deletes nothing. New manifests are grouped and rolled as Java's `writeDataManifests` does, and merged on the first attempt as `MergeAppend` does. The append sink and its open-file cap (`krishiv.iceberg.write.maxOpenFiles`, default 100) are in place, but no catalog commits through them yet (that comes with the catalog clients), so Iceberg tables stay read-only. Persist, unpersist and checkpoint need the operator role. (#844)

(#868)
- A declared Iceberg REST catalog can use `auth = delegated`: each user reaches the catalog as themselves, by an RFC 8693 token exchange of their OIDC token or signed assertion (`delegation = exchange`, the default) or by forwarding a token whose audience names the catalog (`delegation = forward`). (#869)

### Performance

- A hash join now releases its build-side memory as soon as its last probe finishes, so the operator above it no longer (#734)
  spills behind it: TPC-H q16 at scale factor 1000 runs in half the time (69.3 s to 34.5 s, laptop, cold runs).
- Aggregates fold faster: TPC-H q01 takes about 0.82x the CPU cycles at scale factor 10 (decimal arithmetic on 64-bit lanes and decimal `sum`/`avg` kernels), and `sum`, `min`, `max`, `count(column)` and `avg` over integer, date, timestamp, decimal and double columns cost 0.03-0.30x as much per row, measured on 1 Mi `bigint` rows on one core (ungrouped `sum` 0.15x, `min`/`max` 0.10x of the query time). (#743)
- Hash joins keep their build side in fixed-size row blocks with a smaller, denser hash directory, and a join's (#749)
  unused columns are joined in only after the filtering joins above it: TPC-H q21 at scale factor 1000 runs in
  277 s instead of 474 s with no spill (laptop, cold run).
- `count(DISTINCT x)` inside `GROUP BY` is counted while the parallel merge finds each (key, value) pair new, instead of (#795)
  in a second hash aggregation over the pairs: the ClickBench q10 and q14 shapes take 0.66x and 0.72x the time on 6
  threads. Single-threaded and `krishiv.deterministicOrder` runs keep the previous plan;
  `krishiv.exec.agg.distinctCountAtMerge=false` turns it off.
- A join whose probe side is estimated at least 20 times its build now keeps a runtime Bloom filter of up to 20 million keys (32 MiB) instead of falling back to a min/max range, and probes large filters with prefetching (`krishiv.runtimeFilter.bloom.atScale`, on by default). TPC-H SF100 CPU cycles: q04 -32%, q05 -22%, q03 -15%, q09 -14% (12-core server); all 22 queries -2.1% wall on a laptop. It does not help at SF1000, where the order-key builds exceed even the raised cap. (#800)
- A stack of `EXISTS` / `NOT EXISTS` (semi and anti) joins over one input now runs its most selective join first, as TPC-H q21 does with its `NOT EXISTS`. The new optimizer key `krishiv.optimizer.semiAntiJoinOrder` is on by default. (#817)
- Column lineage in `analyze` costs about 2.5x less: over 90 TPC-DS queries it takes about 10 ms instead of 25 ms in all, 4-5 % of analysis time instead of 13-15 % (release build, best of 5 runs per query). (#821)
- A `GROUP BY` that lists both a column and expressions over it (such as ClickBench q36, `GROUP BY ClientIP, ClientIP - 1, ...`) now groups by the column alone and computes the expressions once per group, with the same rows and errors (`krishiv.optimizer.derivedKeysAbove`, on by default). ClickBench q36 on a 12-thread server: 1.05 s to 0.86 s (0.82x, paired ABBA, median of 15 warm runs). (#835)
- `SELECT COUNT(*)` over Parquet files read by path, temporary views created from a DataFrame read of them (`spark.read.parquet(..).createOrReplaceTempView`) and catalog tables now reads only the files' footers, not a column of every row (ClickBench q01). A SQL `CREATE TEMPORARY VIEW .. AS SELECT * FROM parquet.`..`` still reads one column. (#847)
- Joins with a very large build side get a larger runtime Bloom filter, sized from the query memory limit (`krishiv.runtimeFilter.bloom.memoryTier`): TPC-H q05 at SF1000 runs in 0.81x the time, q03 in 0.97x. (#851)
  Small batches from selective filters and joins are joined into full-size batches before hash builds, aggregations and probes (`krishiv.exec.coalesceInput`).
- The final phase of a large hash aggregate allocates each partition's rows and aggregate states once, sized from its group estimate, instead of growing them by doubling, and sizes its key index to that estimate instead of the next power of two above it. TPC-H q18 at SF100 runs 16% faster warm with 19% less peak memory, and ClickBench q33 runs 15% faster with 5% less (server, ABBA x3; q01 and q13 unchanged). A task the memory pool cannot grant that up front merges as before. `EXPLAIN ANALYZE` reports `row_final_presized`. (#858)
  A thread-local aggregate table whose keys are nearly all new now switches to append-only after 2^17 input rows instead of 2^20: TPC-H q13 at SF100 and TPC-DS q22 and q65 at SF10 use about 5% fewer CPU cycles.
- A join whose build side filters with a predicate the optimizer cannot estimate (`LIKE`, string functions, UDFs) now gets a runtime Bloom filter on the probe side when the build turns out small enough, so TPC-H q20 drops most `lineitem` rows at the scan. (#864)
- A table that a query reads more than once now reads, at each read, only the columns that read uses: TPC-H q21 at (#882)
  scale factor 1000 reads 8% fewer bytes (laptop, cold runs).
- Grouped aggregations over input clustered by the key (TPC-H q18's `lineitem` by `l_orderkey`) look up each run of equal keys once and append nearly unique runs without an index; runtime filters reach scans through inner-join key equalities (`krishiv.runtimeFilter.equatedSites`), so q18's `HAVING` keys now filter `lineitem` at the scan; and a `HAVING` over an aggregate's values is evaluated before the group keys are decoded (`krishiv.exec.agg.outputFilter`). TPC-H q18 at SF100 uses about 26% fewer CPU cycles. (#893)
- A hash join whose build side is estimated from a guessed filter (`LIKE`, `HAVING`) keeps a Bloom runtime filter when the build grows past its planned size or spills, so the probe-side scan still drops non-matching rows: TPC-H q09 at scale factor 1000 runs 15% faster (cold, 20 GB memory limit, 12 threads; probe spill 11.2 GB to 2.5 GB). (#904)
- Re-analysing a plan one step longer is cheaper: a warm analysis skips the hint walks and the unexecutable and depth checks over the part an earlier analysis already verified (about 8% fewer instructions at depth 200). (#908)
- Casting a double to a decimal is about 30 times faster (64K fare-like values: 109 ms to 3-4 ms), and casting a double to a string, or writing doubles to CSV and JSON, about 5 times faster (103 ms to 17-20 ms); results are unchanged. (#923)
- Grouping sets (ROLLUP, CUBE, GROUPING SETS) aggregate their input once before expanding it: TPC-DS q22 runs about 10x faster; an aggregate over keys that recur after a first stretch of unique keys no longer stays append-only. (#933)
- TPC-DS queries that repeat a subquery with different filters (q47, q57) compute the shared part once (about 0.55x wall at SF10), widening decimal casts no longer convert row by row (q28 0.31x), and a scan skips a value-list filter already covered by an exact join filter (q68 0.86x CPU cycles at SF10). (#935)
- A `CASE` whose branches cannot raise evaluates each branch on the whole batch (TPC-DS q59 0.72x CPU cycles at SF10), and a table read only by two or more filters is read once and its kept rows shared (q28 0.41x; `krishiv.optimizer.shareFilteredScans`, on by default). (#958)

- A window over spilled partitions no longer fails when a sliding frame's aggregate states need memory while the pool is full: the states are counted in the memory kept back for reading the spilled rows. (#806)
- `krishiv server` (Spark Connect) no longer fails the ML cache cleanup PySpark sends when a client process exits. (#810)
  An operation interrupted or released while its plan is analysed ends with `OPERATION_CANCELED`, an internal failure
  while results are encoded ends the stream with `INTERNAL_ERROR` instead of leaving it waiting, and a released
  operation is no longer reported as abandoned.
- `spark.catalog` in Python now returns what PySpark 4.2 returns: lists of `Database`, `Table`, `Column`, `Function` and `CatalogMetadata` records (PY-026), not DataFrames. `spark.catalog.listCatalogs()` now lists only `spark_catalog` and `setCurrentCatalog` accepts only `spark_catalog` (any other name, `system` included, fails with `CATALOG_NOT_FOUND`); SQL `USE system` still reaches the system tables. `setCurrentDatabase` always takes a database name, so `setCurrentDatabase("system")` no longer switches the catalog. (#812)
- The `vector_*` functions (`vector_inner_product`, `vector_l2_distance`, `vector_cosine_similarity`, `vector_norm`, `vector_normalize`) match Spark 4.2.0 bit for bit: sums run in blocks of 8 as Spark does (a plain fold differed from 8 dimensions up), `vector_norm(v, float('inf'))` skips a NaN element, a NULL element no longer hides a dimension mismatch, and cosine similarity and normalize give NULL below `Float.MIN_NORMAL`. 768-dimension goldens come from a real Spark 4.2.0 run. (#818)
- CSV reads with `enforceSchema=false` check the header as Spark does: by `spark.sql.caseSensitive`, Unicode case folding, only the read columns when pruning; column pruning is off by default under `multiLine`. (#822)
- Aggregates whose answer depends on the order rows arrive in (`first`, `last`, the ties of `max_by`/`min_by`, the sign of a `0.0`/`-0.0` tie in float `max`/`min`, `percentile_approx` and session aggregate UDFs) now give the same answer whether or not the query spilled to disk. (#824)
- A collated string in the condition of `if` no longer gives the result its collation: only the result positions count, as in Spark. (#826)
- The bench runner's memory-bound tests allow for coverage instrumentation, so they no longer fail intermittently in the coverage job. (#828)
- `_metadata.file_path` prints a file under the path as it was read (`s3a://bucket/...` stays `s3a://`, an Azure host as written), and `_metadata.file_name` is the quoted last segment, as in Spark. `input_file_name()`, `input_file_block_start()` and `input_file_block_length()` return the file being read instead of `''` and -1, with Spark's `MULTI_SOURCES_UNSUPPORTED_FOR_EXPRESSION` check. (#833)
- A gzip, deflate or bzip2 CSV/JSON/text file that is cut short now returns the complete lines decoded before the break, as Spark does, both in the scan and (under `ignoreCorruptFiles`) in schema inference; inference errors name the broken file. A read's `ignoreCorruptFiles` option wins over the SQL conf in CSV/JSON scans and, as in Spark, is not trimmed (`" true "` is refused; the conf is still trimmed). A Parquet footer only the scan meets fails with `FAILED_READ_FILE.NO_HINT` caused by the footer error. (#837)
- A query with a Python UDF could stop for good when a UDF call finished at the moment the engine checked whether it (#842)
  could send more rows to Python; mostly seen on free-threaded Python 3.14t with several threads on one session and a
  tight memory limit.
- The dependency check no longer fails on the chrono and humantime "unmaintained" advisories (RUSTSEC-2026-0543, RUSTSEC-2026-0542): neither has a safe upgrade, so both are ignored with their reasons recorded in deny.toml. (#848)
- `krishiv.build_info()` reports the git commit the wheel was built from (`commit`, `"unknown"` for an unstamped build), and the release wheels and CLI binaries are stamped with it (also the `git_sha` label of `krishiv.build.info`). (#853)
- A correlated scalar subquery over a collated string equality on the column's own collation now compares on collation keys instead of raising an error; a correlation under a different collation is still refused. Two different implicit collations in one comparison raise INDETERMINATE_COLLATION_IN_EXPRESSION, as in Spark. (#854)
- Reading only the corrupt-record column of a JSON or CSV file (`select("_corrupt_record")`) now fails with `UNSUPPORTED_FEATURE.QUERY_ONLY_CORRUPT_RECORD_COLUMN` at the first action, as in Spark; `count()`, `select *` and reads that include another column still work. A column name with a NUL character (a UTF-16 CSV file read as UTF-8) now collects and converts to Arrow, as in Spark; a NUL in a nested field name raises `KRISHIV_UNSUPPORTED_FEATURE` instead of an Arrow error (Spark returns the rows; a known difference). In a local run, `first()`, `head(n)`, `take(n)` and `limit(n)` (up to 10,000 rows) over a file scan with no filter now return the first rows of the file, as in Spark, instead of rows from any split; larger limits and distributed runs keep no promised order. (#855)
- Opening one new SQLite catalog file from several connections at the same moment no longer fails with `KRISHIV_CATALOG_FAILURE` ("database is locked"): the open waits for the first connection's setup within the catalog's busy timeout. (#857)
- `count()` of a CSV or JSON read no longer decodes values, as Spark: a CSV count counts lines without tokenizing them (unless `multiLine` or `columnPruning=false`), and a JSON `DROPMALFORMED` count drops only records that are not JSON objects (a value of the wrong type no longer lowers the count). A `multiLine` JSON file is read as its first value only, as Spark reads it (rows, count, the corrupt-record text and schema inference); text after that value is no longer returned as further rows. (#870)
- Optimizing a query twice gives the same plan when a cross-joined subquery is read only for its row count (before, the second run could keep a different column). (#877)
- A query that has to spill while `krishiv.spill.dir` cannot be made, used or locked now fails with `KRISHIV_SPILL_IO_ERROR` naming the directory and the OS error (an invalid `krishiv.spill.*` value keeps its own class), not a bare `UNABLE_TO_ACQUIRE_MEMORY` (PY-078). (#880)
  Reading an `hf://` directory or glob, a missing file, or an `@~parquet` suffix now fails with a clear error naming what to use instead; the README names how to install the `krishiv` CLI (KN-7, RS-1).
- A large `GROUP BY` with nearly every key distinct no longer spills twice the bytes, or fails with `UNABLE_TO_ACQUIRE_MEMORY`, near its memory limit: the final phase sizes its tables up front only when memory for its inputs is free beside them (TPC-H q16 at SF1000 had slowed from 53 s to 100 s). (#884)
- The coverage check of a pull request may now run for 90 minutes instead of 60, so checks of changes to the session layer are much less likely to be cancelled for running out of time. (#894)
- The `start_local()` test no longer fails now and then on macOS: its port check binds with `SO_REUSEADDR`, so a closed connection in `TIME_WAIT` does not count as a port in use. `start_local()` itself is unchanged. (#912)
- A `Dataset.observe` observation completes when its action is killed, timed out or cancelled during its setup with that action's own error, and when the only read of an observed temporary view is inside a SQL function body. A shared CTE read both live and under `LIMIT 0` runs its body once, and one read only under `LIMIT 0` reports nothing, as in Spark. (#915)
  Connect `ObservedMetrics` carry struct, map, binary, year-month, day-time and calendar-interval metrics as literals. A task buffer whose metric merge overflows (a long `sum` under ANSI) is dropped, as in Spark, instead of failing the action; task states merge in partition order. A metric observed above a proven-empty relation (`where(false)`) is pruned with it. The limit-shape differences are tabulated in `docs/concepts/known-differences.md`.
- The weekly fuzz job's Parquet read target no longer runs out of memory: it leaked one memory-pool consumer entry per scan. (#920)
- A command's missing-table error (DESCRIBE, DROP VIEW, UNCACHE and the other commands) now ends its search path at the current database, as Spark does after USE. (#936)
- `variant_get` and `try_variant_get` name their output column without the type argument, as Spark 4.0 to 4.3 do. (#955)
- A query whose filter compares a repeated expression with a column (for example `c + 1 = c` beside `c + 1 IN (2, 3)`) above an outer join now gets the same plan when optimized again. (#964)
- Fixed: `url` 2.5.9 for RUSTSEC-2026-0592 so `cargo deny` passes again; the chrono ignore (RUSTSEC-2026-0543) carries a review date. (#971)

### Security

- With authentication configured, the `krishiv server` admin listener (`/metrics` and the web UI) asks for credentials and checks the caller's role (viewer, operator or admin). (#736)
- - Access policies see one canonical `file:` path for every check on a managed table's directory (links and `..` resolved, relative paths refused), so one path rule gives the same answer for CREATE, INSERT, DROP, RENAME and partition DDL; a denial no longer reveals whether a path exists. `SHOW`/`DESCRIBE` result columns carry Spark 4.2.0's nullability. (#799)
- A silent Spark Connect `Config.set` that fails no longer repeats a secret value in its warning: when the key or the value matches the redaction rules (a token, a password, credentials in a URL), the warning shows `Some(*********(redacted))`, also where the error message would repeat the value. Spark prints the value as given. (#891)
- A refused or invalid setting (SQL `SET`, Spark Connect `Config.set`, PySpark `conf.set`) no longer repeats a secret value, such as a token or a URL holding credentials, in its error; the key is still named. (#906)
- A bare `DROP VIEW v` of a stored view now checks the Drop privilege on that view and transfers its grants, as `DROP TABLE` does. Before, a user who held only `CREATE` on the schema could drop another user's view. A draining server now refuses the statement as DDL. (#952)

## 0.2.0

The first release is the embedded core: the engine runs in your process, from Python or Rust.

### Highlights

- **Embedded Spark-compatible engine.** `krishiv.session()` gives a PySpark-style session in your process, from Python or
  Rust, with no JVM; Spark-observable behaviour is checked against real Spark runs.
- **Memory-bounded and fast.** A vectorized Arrow executor that spills aggregation, joins, sorts and window frames to disk
  instead of failing, with runtime filters, Parquet row-group and dictionary pruning, and a cost-based join order.
- **Broad SQL.** Windows (`ROWS`/`RANGE`), `GROUPING SETS`, lateral joins, recursive CTEs, SQL scripting, `CHAR`/`VARCHAR`,
  collations, `VARIANT`, calendar intervals, `GEOMETRY`/`GEOGRAPHY`, `PIVOT`, `TABLESAMPLE`, SQL functions and `IDENTIFIER(..)`.
- **Python UDFs in process.** `@udf`, scalar `pandas_udf` and `arrow_udf` run on a thread pool, in parallel on free-threaded 3.14t.
- **See what happened.** `EXPLAIN [ANALYZE|COST|VERBOSE]`, a versioned JSON profile with per-scan I/O, a local web console,
  Prometheus metrics, OTLP spans and JSON logs, and errors that show the SQL span that raised them.
- **Zero-copy interop** with pyarrow, Polars and DuckDB through the Arrow PyCapsule interface.

### Added

- In-process batch SQL and DataFrames over Arrow: `krishiv.session()` returns a PySpark-style `SparkSession`
  (`sql`, `read.parquet`, temp views, `select`/`filter`/`groupBy`/`agg`/`orderBy`/`withColumn`, `collect`, `show`,
  `toArrow`, `toPandas`, `count`).
- Zero-copy Arrow interop through the Arrow PyCapsule interface (`__arrow_c_stream__`): pyarrow, Polars and DuckDB
  read a DataFrame's result without copying buffers.
- `EXPLAIN [EXTENDED | FORMATTED | CODEGEN | COST]` with Spark's section layout, `EXPLAIN ANALYZE` (per-operator rows,
  time, peak memory and spill bytes, as text and as a versioned JSON profile) and `EXPLAIN VERBOSE` (optimizer steps).
- A vectorized, Arrow-native executor with memory-bounded spilling hash aggregation, hash joins (including grace
  partitioning), sorts and Parquet scans with runtime filters.
- `krishiv sql`, a command line SQL shell (script mode, table/CSV/JSON output, `--timing`).
- Python wheels for Python 3.11+ (`abi3`) and free-threaded 3.14t, for manylinux x86_64 and aarch64, musllinux
  x86_64 and macOS arm64, built for x86-64-v3 and neoverse-n1, with a `krishiv-compat` wheel for older x86-64 CPUs.
  The import checks the CPU and says which feature is missing instead of crashing.
- Spark error classes and the configuration registry, so errors read as Spark's do.
- Errors raised at a span of SQL show it: `krishiv sql` and the text of Python exceptions from `spark.sql` follow the
  message with an `== SQL (line, position) ==` block, the source line and a caret under the span (a syntax error
  instead shows Spark's `ParseException` layout with its 0-based position).
- Spark SQL coverage: window functions with `ROWS` and `RANGE` frames (day-time and year-month interval bounds
  too), `GROUPING SETS`/`CUBE`/`ROLLUP`, lateral joins, generators in `FROM`, recursive CTEs, and the JSON, CSV and
  XML functions with Spark's option names (the legacy `FastDateFormat` patterns included).
- Reads over `hf://` (Hugging Face datasets), and credential refresh and per-location scopes for object stores.
- Telemetry: OTLP export of query spans and engine metrics behind the `telemetry-otlp` feature.
- Optimizer: eager aggregation below joins.
- Results checked against real Spark runs: division and remainder evaluate their operands in Spark's order, `atan2` is
  bit-identical.
- Python UDFs: `@udf`, scalar `pandas_udf` and `arrow_udf` run in process on a thread pool.
- Collations (`UTF8_LCASE`, `_RTRIM`, `COLLATE`, collation-key comparison and operators, Parquet collation metadata).
- `VARIANT` in Parquet at any depth; `GEOMETRY` and `GEOGRAPHY` types with five `st_` functions (`st_asbinary`, `st_geomfromwkb`, `st_geogfromwkb`, `st_setsrid`, `st_srid`: WKB and SRID, no WKT); `CALENDAR INTERVAL`;
  `CHAR(n)`/`VARCHAR(n)`; `MSCK`, partition commands and column statistics; SQL scripting with exit handlers.
- Deterministic row order (`krishiv.deterministicOrder`), `krishiv.optimizer.joinCost=bytes`, plan-time distinct-value
  samples of Parquet columns, and inferred join filters.
- A local web console (`krishiv.ui.enabled`), a bearer-token guard for `/metrics`, per-scan I/O fields in the profile, JSON
  logs, and a `--share` profile that drops identity and trace ids.
- `krishiv sql` has a line editor (history, cursor movement, multi-line input), `USE system` and the `system.queries`
  table of recent queries and their columns.
- Parquet writes are checked for interop with other readers: nulls at every nesting level and column statistics.

### Known limits

- Spark Connect, streaming, incremental views and distributed execution are not part of this release.
- The APIs are not stable.
