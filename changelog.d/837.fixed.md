A gzip, deflate or bzip2 CSV/JSON/text file that is cut short now returns the complete lines decoded before the break, as Spark does, both in the scan and (under `ignoreCorruptFiles`) in schema inference; inference errors name the broken file. A read's `ignoreCorruptFiles` option wins over the SQL conf in CSV/JSON scans and, as in Spark, is not trimmed (`" true "` is refused; the conf is still trimmed). A Parquet footer only the scan meets fails with `FAILED_READ_FILE.NO_HINT` caused by the footer error.
