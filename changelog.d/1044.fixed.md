With no `krishiv.memory.limit` set, a small container no longer gets its process killed by the kernel during a large join or group-by: the default memory limit now leaves at least 512 MiB of the container's memory outside the query memory pool (but never takes more than half of it). A 1 GiB container now gets a 512 MiB pool (was 819 MiB) and a 2 GiB container 1.5 GiB (was 1.6 GiB); from 2.5 GiB up the default is 80% as before.
