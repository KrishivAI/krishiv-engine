The Spark Connect translator decodes `mapInPandas`/`mapInArrow`, `groupBy().applyInPandas`/`applyInArrow` and `cogroup().applyInPandas`/`applyInArrow` plans into the engine's Python UDF relations, given a host that names their UDFs, and the analyzer resolves those relations and refuses a grouped or cogrouped map over a nondeterministic UDF with Spark's `INVALID_NON_DETERMINISTIC_EXPRESSIONS`. No client can reach this yet: the Connect server passes no host, and the UDF worker pool cannot run these relations (`prepare_relation`), so they are still refused end to end.
