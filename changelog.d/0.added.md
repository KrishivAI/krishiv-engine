`spark.read.schema(...)` and `schema=` on `spark.read.csv`/`json`/`load` now read the files as the given columns (a `StructType` or a DDL string such as `"id INT, name STRING"`) instead of failing; Spark Connect reads with a schema too, and the Rust `DataFrameReader` gains `schema` and `schema_ddl`. As in Spark, every column reads as nullable, `k=v` partition columns come last, typed by the schema when it names them (a value that does not read as that type is `INVALID_PARTITION_VALUE`, or NULL with `spark.sql.sources.validatePartitionColumns=false`), and under `spark.sql.caseSensitive=true` Parquet columns match by exact name. A read whose data files also hold a partition column now keeps that column at its place with the directory's value, instead of failing (KN-1, PY-018, PY-030).
