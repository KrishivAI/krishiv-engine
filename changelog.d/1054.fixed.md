Under `spark.sql.timestampType = TIMESTAMP_NTZ`, a bare `TIMESTAMP` type (and Spark 4.3's `TIMESTAMP(6)`) is now `TIMESTAMP_NTZ` in SQL casts, column types and views, in Spark Connect cast targets and schema strings, in the schemas of `from_json`, `from_csv` and `from_xml` and the types of `variant_get` / `try_variant_get`, and in the return type of a UDF registered on a session. A view keeps the timestamp type that was in force when it was created. Also: `date_format` of a `TIME` under Spark 4.2 is refused as Spark refuses it (`CAST_WITHOUT_SUGGESTION`), and a `TIMESTAMP` near the end of the supported range casts to its `TIME` of day instead of failing with `DATETIME_OVERFLOW`. A function call whose `TIME` argument Spark refuses to cast (for example `datediff(array(1), TIME'12:00:00')`) now reports that cast (`CAST_WITHOUT_SUGGESTION`) before a mismatch of an earlier argument, as Spark does; `date_add` and `date_sub`, which Spark never casts a `TIME` for, report a `TIME` start as `UNEXPECTED_INPUT_TYPE`.
