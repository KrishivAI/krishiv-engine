A hash aggregate's row table whose input keeps bringing new keys (measured by the input's distinct keys per row from about 2^16 to 2^17 rows, not by the rows the table made) spreads its rows over more radix partitions (widens) at its first decision, after 2^17 rows, instead of at the end of its input, so fewer rows are copied when it widens. An input whose keys repeat (TPC-DS q22) still widens at the end. `EXPLAIN ANALYZE` reports `row_widens_early`, `row_widens_late` and `row_widened_rows` on each `HashAggregate`.
