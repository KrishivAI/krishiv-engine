`krishiv server` drains on SIGTERM and through the admin API (`Drain`, `GetDrainStatus`, `ResumeServing`, `GetReadiness`): `/readyz` answers 503 first, new queries and sessions are refused with `KRISHIV_SERVER_DRAINING` (a query that reads only `system.*` is still served, so operators can inspect the drain) (never retried by the stock Spark Connect client), running queries finish until `krishiv.server.shutdownTimeout` and are then cancelled. `/readyz` answers from cached checks (`krishiv.server.readiness.*`).
