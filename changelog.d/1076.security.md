A `krishiv server` session (Spark Connect, Flight SQL, the console's SQL editor) no longer replaces `${env:NAME}` and `${system:NAME}` in SQL text with the server's environment, so a signed-in client cannot read the server's secrets. Set `krishiv.server.sql.substituteEnvironment=true` at server start to restore Spark's behaviour; embedded sessions are unchanged. A `${name}` reference to a setting that `SET` and `Config.get` hide (a secret-like key or a value holding a credential) also stays as written in a server session.
