Web console of a server with TLS: a browser could not sign in. A browser speaks HTTP/2 to a TLS listener, and an HTTP/2 request names the server in `:authority`, not in a `Host` header, so the console's same-origin check refused the page's own sign-in (`403 bad_origin`), and on a loopback listener the host check refused every request (`403 bad_host`). This affected `krishiv server` with `krishiv.server.tls.*` and the Docker image. The host check, the same-origin check and the session cookie's name now read the authority when there is no `Host` header. The page shown without a token now also says how to open the console of a server with configured tokens (add `?token=` and the token to the address).
