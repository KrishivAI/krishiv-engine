A syntax error after an operator followed by a keyword now names the token and position Spark 4.2.0 names: `SELECT (1 +` then `FROM range(1)` on the next line reads `FROM` as a column and `range` as its alias, so the error is at the `(` (line 2, pos 10), not at `FROM`. An unclosed call with an argument that is more than a name or a literal no longer adds a `missing ')'` hint that Spark does not give; beside another argument it reports the extra input as Spark does.
