A hash join whose condition also compares a probe-side column with a build column (`p < b`, `p <= b`, `p > b`, `p >= b` on numbers, dates or timestamps) publishes the build's largest (or smallest) value as a runtime filter, so the probe scan drops the rows no build row can match before the join (TPC-DS q72's `inv_quantity_on_hand < cs_quantity`). `krishiv.runtimeFilter.residualBounds` (default on) turns it off.

The join orderer also plans the small fact-to-fact block first when the largest fact table has a clustered column on that block's composite key, so the small block's keys become a runtime filter that skips most of the large scan's row groups (TPC-DS q17, q25, q29: 0.26-0.46x instructions). `krishiv.optimizer.joinPruneFirst` (default on) turns it off.
