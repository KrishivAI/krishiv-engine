Grouped aggregations over input clustered by the key (TPC-H q18's `lineitem` by `l_orderkey`) look up each run of equal keys once and append nearly unique runs without an index; runtime filters reach scans through inner-join key equalities (`krishiv.runtimeFilter.equatedSites`), so q18's `HAVING` keys now filter `lineitem` at the scan; and a `HAVING` over an aggregate's values is evaluated before the group keys are decoded (`krishiv.exec.agg.outputFilter`). TPC-H q18 at SF100 uses about 26% fewer CPU cycles.
