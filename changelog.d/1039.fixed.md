Web console: a query sent over Spark Connect with `spark.sql(...)` is listed with its statement text and class, also when the client calls `count()`, `filter(...)` or `first()` on it (they were shown as "–" and the statement filter could not find them). Sessions no longer lists a server's internal template sessions, and the editor's own session is marked only once it has run a statement. Resources shows memory pools of one name as one row. Environment shows the Spark name a setting also answers to and finds it by that name. In the SQL editor, Ctrl or Cmd + Enter runs the statement (it added a blank line), and typing over a selection no longer logs a content-security-policy error. An embedded page refuses and logs a theme message when the allowed origins cannot be read, a hash that is not `#/...` is no longer read as a page, and `krishiv.ui.allowedOrigins` refuses a port written with a leading zero.

Python: `import krishiv` warns when `krishiv` and `krishiv-compat` are installed in the same environment (pip accepts both, the later one overwrites the earlier one, and uninstalling either leaves a broken package); the install page says how to repair it, and what pip's "No matching distribution found" means on Python 3.10 or older.

Docs: three statements of the known-differences page now say what 0.3.0 does. A `LIMIT` above `DISTRIBUTE BY` skips a raising value only in a batch it never reads; a declared schema on a Delta read is refused by `load` (embedded) or by the first call sent to the server (Spark Connect), `df.schema` included; the embedded `mapInArrow` and `mapInPandas` raise `KRISHIV_INVALID_ARROW_DATA`, `INTERNAL_ERROR` or `PYTHON_EXCEPTION` for a result unlike the declared schema, by case. The README says the MCP server for AI agents is in the source tree (`krishiv mcp`, the `mcp` feature of `krishiv-cli`) and not yet in the release binaries, the Docker image or the wheels. The collations guide lists which builds have ICU collations (the `krishiv` binary and the Docker image have them, the Python wheels do not), what a build without them raises, and the Spark Connect route from Python.

SQL: `CREATE VIEW` of a metric view without `WITH METRICS` or `LANGUAGE` raises `MISSING_CLAUSES_FOR_OPERATION` (SQLSTATE 42601) and names the clause, as Spark 4.3 does; it was `INTERNAL_ERROR`. Under the Spark 4.2 setting it stays Spark 4.2's internal error.

MCP server (source builds): a link in `--data` whose target is outside the directory no longer makes every tool call fail; it is left out, as is a file that cannot be read as Parquet, and `list_tables` and `search_tables` name what was left out and why. `sql_reference` takes a pattern (`date*`, `%trunc%`, `abs|sum`) and prints the argument counts as `2` or `[2, 3]`. A call refused because four calls already wait raises `KRISHIV_MCP_QUEUE_FULL` (SQLSTATE 53400); it was `INVALID_PARAMETER_VALUE`.
