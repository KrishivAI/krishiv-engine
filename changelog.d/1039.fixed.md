Web console: a query sent over Spark Connect with `spark.sql(...)` is listed with its statement text and class, also when the client calls `count()`, `filter(...)` or `first()` on it (they were shown as "–" and the statement filter could not find them). Sessions no longer lists a server's internal template sessions, and the editor's own session is marked only once it has run a statement. Resources shows memory pools of one name as one row. Environment shows the Spark name a setting also answers to and finds it by that name. In the SQL editor, Ctrl or Cmd + Enter runs the statement (it added a blank line), and typing over a selection no longer logs a content-security-policy error. An embedded page refuses and logs a theme message when the allowed origins cannot be read, a hash that is not `#/...` is no longer read as a page, and `krishiv.ui.allowedOrigins` refuses a port written with a leading zero.

Python: `import krishiv` warns when `krishiv` and `krishiv-compat` are installed in the same environment (pip accepts both, the later one overwrites the earlier one, and uninstalling either leaves a broken package); the install page says how to repair it, and what pip's "No matching distribution found" means on Python 3.10 or older.

Docs: four statements of the known-differences page now say what 0.3.0 does. A `LIMIT` above `DISTRIBUTE BY` skips a raising value only in a batch it never reads; a declared schema on a Delta read is refused by `load` (embedded) or by the first call sent to the server (Spark Connect), `df.schema` included; a metric view without `WITH METRICS` or `LANGUAGE` is `INTERNAL_ERROR` under the default Spark 4.3 too; the embedded `mapInArrow` and `mapInPandas` raise `KRISHIV_INVALID_ARROW_DATA`, `INTERNAL_ERROR` or `PYTHON_EXCEPTION` for a result unlike the declared schema, by case.
