Reading only the corrupt-record column of a JSON or CSV file (`select("_corrupt_record")`) now fails with `UNSUPPORTED_FEATURE.QUERY_ONLY_CORRUPT_RECORD_COLUMN` at the first action, as in Spark; `count()`, `select *` and reads that include another column still work. A column name with a NUL character (a UTF-16 CSV file read as UTF-8) now collects and converts to Arrow, as in Spark; a NUL in a nested field name raises `KRISHIV_UNSUPPORTED_FEATURE` instead of an Arrow error. `first()`, `head(n)`, `take(n)` and `limit(n)` over a file scan with no filter now return the first rows of the file, as in Spark, instead of rows from any split.
