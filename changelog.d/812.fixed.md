`spark.catalog` in Python now returns what PySpark 4.2 returns: lists of `Database`, `Table`, `Column`, `Function` and `CatalogMetadata` records (PY-026), not DataFrames. `spark.catalog.listCatalogs()` now lists only `spark_catalog` and `setCurrentCatalog` accepts only `spark_catalog` (any other name, `system` included, fails with `CATALOG_NOT_FOUND`); SQL `USE system` still reaches the system tables. `setCurrentDatabase` always takes a database name, so `setCurrentDatabase("system")` no longer switches the catalog.
