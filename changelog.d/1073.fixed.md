`hash` and `xxhash64` over arrays, maps and structs that hold strings, and `greatest` / `least` over mixed string
columns, no longer fail; they return Spark's values. Tables registered from Arrow data (Python `createDataFrame`,
`Session::register_batches`) now run: their string columns come back as `string_view`, and nested fields take
Spark's names (`element` for a list, `entries` / `key` / `value` for a map) instead of pyarrow's `item`.
