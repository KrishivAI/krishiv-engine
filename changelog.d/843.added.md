Iceberg write, part 2: appends commit through a loop that never retries blind. An unknown answer is checked against the table, and only the same attempt is resent, or the write is rebased once the branch has moved. A write whose outcome stays unknown deletes nothing. New manifests are grouped and rolled as Java's `writeDataManifests` does, and merged on the first attempt as `MergeAppend` does. An Iceberg table opened at its current version with a committer accepts batch appends through its sink. The open-file cap of a write task is `krishiv.iceberg.write.maxOpenFiles` (default 100).
