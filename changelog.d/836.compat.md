In server mode, `SET` and `RESET` of catalog declaration keys (`krishiv.catalog.<name>.*`, `spark.sql.catalog.<name>`, `spark.sql.catalog.<name>.*`) fail with `CANNOT_MODIFY_STATIC_CONFIG` for every role, where Spark accepts them at runtime; catalogs are declared at startup only. `SHOW CATALOGS` and `spark.catalog.listCatalogs` list every declared catalog the caller may see, including ones no query has used yet, while Spark lists only catalogs already loaded. While a declared catalog is current, the `spark.catalog` namespace and table calls (`listDatabases`, `getDatabase`, `databaseExists`, `listTables`, `getTable`, `tableExists`, `listColumns`) fail with `KRISHIV_UNSUPPORTED_FEATURE` for a name the current catalog would resolve (temporary views excepted) or one qualified with a declared catalog, since declared catalogs resolve names in queries only for now; `spark_catalog.<db>` names still work, and a `Database` row always names `spark_catalog`.
