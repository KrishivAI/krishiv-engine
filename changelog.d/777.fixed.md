Errors raised while a query runs (for example a failed cast or a division by zero under ANSI mode) now point at the part of the SQL that caused them, in the CLI, the session API and Python, as they already did for errors found while planning. Timestamp filters and conversions in region time zones such as `Europe/Stockholm` no longer look up the zone's offset row by row, and offsets now come from a transition table: time-zone-sensitive scans are several times faster.
