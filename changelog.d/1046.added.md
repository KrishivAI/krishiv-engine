`JOIN ... NEAREST BY` returns the `k` nearest right rows per left row; with `spark.sql.legacy.interval.enabled` an interval literal is a calendar interval (the session now passes that flag to the parser); a zone after a special value (`timestamp 'tomorrow EST'`) is checked and ignored, a NULL ranking never matches, and `SELECT FROM t` reads as Spark reads it.
 `ORDER BY` (and a sort-merge join key) over a struct or an array orders as Spark does, field by field and element by element with NULL smallest; before it raised `KRISHIV_UNSUPPORTED_FEATURE`. A struct or array key with a `NULLS FIRST/LAST` that differs from its direction's default is still refused.
 `greatest` and `least` over structs and arrays compare field by field and element by element with NULL smallest, as Spark does; before they raised `KRISHIV_UNSUPPORTED_FEATURE`.
