A spilled aggregation with many groups now splits its spilled state into more partitions on a machine with more threads (8 to 64, fewer when a smaller memory limit would leave each spill file too small to write efficiently), so its disk phase runs in parallel: db-benchmark groupby q10 (1e8 rows) at an 8 GB limit 0.68x, peak memory 8.6 to 7.4 GB, on a 12-CPU build server. Under `krishiv.deterministicOrder` the partitioning is unchanged.

A hash join whose probe batch matches exactly one build row per row, in order, passes the batch through without copying it: TPC-DS q99 user CPU 0.905x, q62 0.859x at SF10 on the same server.
