# Add an error class

Errors are `KrishivError` values with a Spark error class and SQLSTATE. The registry is generated by
`crates/krishiv-common/build.rs` from three JSON files of the same shape (Spark's, the vendored Delta subset,
Krishiv's).

## First choice: a Spark class
If Spark raises this error, use its class. Spark's file is vendored verbatim and refreshed by
`python3 tests/scripts/gen_error_classes.py` (needs Docker; it also regenerates the render fixture
`tests/fixtures/spark-4.2.0/error-classes/render.json`). Never edit
`crates/krishiv-common/vendored/spark-error-conditions.json` by hand. Look the class up there and use its parameters
exactly.

## A Delta class (delta-spark 4.4.1)
Delta Lake's classes are not in Spark's file. The subset Krishiv raises is vendored in
`crates/krishiv-common/vendored/delta-error-classes.json`: each entry copied verbatim (message lines, sub-classes,
SQLSTATE) from delta-io/delta tag `v4.4.1`, `spark/src/main/resources/error/delta-error-classes.json`. Fetch the file
at the tag (`gh api -H 'Accept: application/vnd.github.raw' 'repos/delta-io/delta/contents/spark/src/main/resources/error/delta-error-classes.json?ref=v4.4.1'`;
never from memory), copy the new entry in key order with the same two-space ` : ` layout, and keep it verbatim
(`delta_classes_equal_the_vendored_subset` checks every leaf). `build.rs` requires the `DELTA_` prefix and a
SQLSTATE there; `DELTA_VERSION_NOT_FOUND` becomes `ErrorClass::DeltaVersionNotFound` and the struct
`DeltaVersionNotFound`. List the class in `crates/krishiv-connectors-delta/src/lib.rs`'s crate docs.

## A Krishiv-only class
1. **Entry** in `crates/krishiv-common/krishiv-error-classes.json`, keyed alphabetically:
   `"message"` as an array of lines with `<param>` placeholders, and a `"sqlState"` (required for `KRISHIV_*`;
   five characters, digits and capitals). The name must start with `KRISHIV_`. `build.rs` fails the build on a
   wrong prefix, a missing SQLSTATE, a bad name or two names that map to one Rust name.
2. **Generated type.** `KRISHIV_SPILL_CAP_EXCEEDED` becomes `ErrorClass::KrishivSpillCapExceeded` and a struct
   `krishiv_common::error::KrishivSpillCapExceeded` with a `String` field per parameter (snake case:
   `<capBytes>` becomes `cap_bytes`). Build an error with `Struct { .. }.into()` (model:
   `crates/krishiv-memory/src/spillfile/error.rs`).
3. **Message text.** Say what happened and the fix, name config keys in quotes, and never put a secret or
   credential in a parameter (redaction: `crates/krishiv-common/src/redact.rs`).
4. **Tests.** The registry tests in `crates/krishiv-common/src/error/tests.rs` (`registry_is_consistent`,
   `krishiv_specific_classes_are_prefixed`) cover shape; add a test at the use site that the right class is raised
   (model: the `ErrorClass::KrishivSpillCapExceeded` assertion in `crates/krishiv-memory/src/spillfile/tests.rs`).
5. **Reference docs.** `cargo xtask docs-errors` prints the table; check the new row. Not committed.

## Verify
`cargo nextest run -p krishiv-common --no-tests=pass` plus the crate that raises it; clippy `-D warnings`.
